## Problem Statement

抓包对拍（46 帧 + 底钓2 274 帧 4/22 快照，见
`docs/实测博鱼过程对装备磨损的影响分析.md`）证实官服磨损与我们的模型是两种口径：

- **官服只按"受力时间"扣**：17s 搏鱼窗口轮油/主齿轮/导环 ≈0.0004%/s 连续下降；
  脱钩后 92s 空竿收线（74 条 14/7 遥测）全部零件零磨损；结算前后耐久连续无跳变。
  我们按"每抛一竿扣一笔基准"记账（空竿也扣），典型日会话（30 抛 + 10 场 30s 搏鱼）
  轮油磨 ~9.6%，官服同口径 ~0.11%——**约 90 倍过快**（轴承 ~20×、主齿轮 ~8×、线杯 ~7×）。
- **官服旋钮（category 34）与手柄（4）永不磨损**；我们把 34 当"摇柄"每竿扣 0.03%。
- **竿侧零件官服搏鱼期间明显磨损**：导环（5）路亚场并列最快 ~0.0004%/s、竿坯（36）
  ~0.00003%/s，我们完全未建模；且竿出厂子件（`buildFactoryChild`）每次快照现建、
  不落库，子件耐久无处持久化。
- **前导（57）官服有渐进磨损**：底钓2 场 412s 搏鱼磨 0.019%（≈0.00005%/s，W5 重载窗
  峰值 0.00012%/s），我们前导没有渐进磨损通道（只有断线事件）。
- **官服搏鱼中每 ~2s 经 4/22 逐帧下发零件耐久**，玩家看着数字掉；我们只在结算后
  落库推送，搏鱼中数字不动。
- **摩擦片打滑磨损快 ~23 倍且无门槛**：官服 W5 实测 112s 重度过载打滑（拉力 2.2×
  泄力）只磨 0.027%（≈0.00024%/s），拉力仅超泄力 1.04× 时零磨损；我们按
  0.01%/1.8s（≈0.0056%/s）计，且只要 pull>drag 就磨。

玩家侧后果：保养品（轮油）和摩擦片变成"按抛竿数日抛耗材"，与官服"小时级保养品"
（轮油 1.0→0.9 需 ~7 小时纯搏鱼）相差两个量级；空竿多的玩法被额外惩罚。

## Solution

磨损只在搏鱼时走表：搏鱼多久，轮内零件（轮油/主齿轮/轴承/线杯）、竿上零件
（导环/竿坯）、前导、摩擦片（真出线打滑时）就按秒掉一点耐久，数字在搏鱼中就能
实时看到往下走；空抛、等待、收线一律不扣。旋钮/手柄永不磨损，钩只有断钩事件。
前导磨耐久同时按既有口径削弱前导强度（`applyDurability` 闭环已存在）。
工坊修理/换件/计价流程不变，修理照常把磨损恢复。

## User Stories

1. 作为玩家，我希望搏鱼时能在客户端看到装备耐久逐帧下降，以便磨损有体感。
2. 作为玩家，我希望空竿、等口、收线不掉任何耐久，以便"打龟一天"不再白磨装备。
3. 作为玩家，我希望轮油从"几天烧完"变成"几十小时搏鱼才耗尽"，以便保养是低频决策。
4. 作为玩家，我希望只有真正拉动泄力出线才磨摩擦片，以便轻微超力的搏斗不白烧片。
5. 作为玩家，我希望重载搏鱼（大鱼顶泄力）磨前导、导环更快一点，以便装备选择有区分度。
6. 边界：断线/断竿仍有一次冲击账；同一竿中途落库与最终结算不重复扣；结算前后
   耐久连续；掉线重连后账本只结一次（既有幂等接缝不变）。

## Implementation Decisions

### 1. 消耗矩阵换通道（reel_part_wear.go）

- `reelPartWearRates` 新增 `perStressSec`（百分点/受力秒）。矩阵值（全部走 tunable，
  缺省即官服实测档位，键不变、按 category 寻件）：

  | category | 部件 | perStressSec (%/s) | 官服依据 |
  |---|---|---|---|
  | 10 | 轮油 | 0.0004 | lure2 0.00038 / 底钓2 0.00007，取存档方案档位 |
  | 52 | 主齿轮 | 0.0004 | lure2 0.00039 / 底钓2 0.00011 |
  | 5 | 导环（竿） | 0.0004 | lure2 0.00041 / 底钓2 0.00025 |
  | 7 | 轴承 | 0.00012 | lure2 0.00014 / 底钓2 0.000024 |
  | 8 | 线杯 | 0.00012 | lure2 0.00012 / 底钓2 0.00002 |
  | 36 | 竿坯（竿） | 0.00003 | lure2 0.00003 / 底钓2 0.000021 |

  竿侧件（5/36）与轮侧件共用同一矩阵与同一应用函数（`selectedReelPart` 按
  def.Category 扫任意字段树，竿树直接复用）；竿侧品类清单 `rodWearPartCategories =
  {36, 5}`，handle（4）不入清单。
- **旧通道置 0**：`perRod`/`perSoak`/`perSlip`/`perOverloadSec` 全部置 0（结构体字段
  保留，回滚 = 还原矩阵字面量）。依据：官服空竿零磨损；打滑/过载窗口的零件磨损已被
  受力通道覆盖（W5 重载窗速率仅为基线 3–10×，属负载相关性，函数形式未解，不设单独
  通道）。电机（81）通道保持不变——官服无电轮样本。
- **category 34 摘除**：从矩阵与 `reelWearPartCategories` 删除，注释更名
  "旋钮 knobs（官服实测不磨损）"。本体聚合权重、熔断件清单不动（旋钮恒 1.0 只是
  常数项，最小 diff）。
- **品质系数 Fq 保留**：标定约定为"品质 100 = 官服实测速率"；低品质更快是既有
  经济设计，标注为与官服的已知偏差（官服样本 workmanship 未知）。
- **负载倍率预留不启用**：tunable `wear_load_multiplier` 缺省 1（关闭），等抓包
  样本能辨识函数形式再开。

### 2. 前导受力磨损（新通道，独立物品行）

- 速率常量 `leaderWearPerStressSec = 0.00005`（tunable `wear_leader_per_stress_sec`；
  底钓2 单场实测 0.000047，W5 峰值 0.00012，取平坦基线）。
- 前导 GUID 沿用承力链既有解析：`ListRigComponents(rodGUID)` →
  `compGUIDs[gearCatLeaderWire]`，回退 `gearCatLeader`（gear_physics.go:781-785 同源）。
- 落库直接写前导物品行 Durability（单调只降）；前导强度已经吃
  `applyDurability(leaderKg, LeaderDurability)`，磨损即削弱强度，无需新增联动。
- 无前导的装配（含自制引线无实例的旧档）跳过，不算假账。

### 3. 竿子件持久化地基（rebuildRod 不改现建语义，增量合并）

- 竿出厂子件 f0/f1/f2 目前只在推送快照里现建（`wiregen.MakeObj`，GUID =
  md5(rodGUID|rod/handle/third)），DB fields JSON 里没有子件，耐久无处写。
- 方案：**磨损/修理路径物化、快照路径合并**——
  1. 磨损写入前若竿 DB fields 无子件，按同一 GUID 派生规则与 `buildFactoryChild`
     同源物化三件进 fields JSON（只填空槽，与 `materializeInto` 同规）；
  2. `rebuildRod` 现建子件后，按子件 GUID 从竿 DB fields 里把已持久化的耐久
     （及未来其它有状态字段）拷到现建对象上再赋槽——现建语义、状态位来源、
     客户端收线输入兼容性全部不变，只多一步耐久回填；
  3. 老档首次磨损即物化，之后续接。
- 竿本体耐久聚合不在本方案范围（官服未分析竿顶层数字）。

### 4. 账本与结算（reel_fight_wear.go）

- `fightReelWear` 新增 `StressSecs`；`recordFightReelLoad` 在现行 hooked 窗口内按
  既有真实 tick（首条 1.9s 兜底、间隔上限 5s）无条件累加——与打滑判定解耦
  （n.pike 全程无打滑仍磨损）。`claimLocked` 空账判定加 `StressSecs > 0`；
  `partCounts` 增加受力秒透传；`rollFightWearLedgerLocked` 的 newCast 打基准逻辑
  保留为空转（最小 diff，注释标明 perRod 已停用）。
- `applyFightReelWear` 一次写三棵树：轮树（矩阵 7/8/10/52 + 摩擦片既有通道）、
  竿树（矩阵 5/36）、前导行（Durability）。竿 GUID 账上已有，前导 GUID 按第 2 节解析。
- **负载倍率 v1 不做**（见第 1 节），`StressSecs` 累加保持平坦。

### 5. 摩擦片打滑重校与锁轮烧穿曲线删除（用户已裁定，2026-11-11）

- **打滑门槛**：pull ≤ drag×1.05 不磨，tunable `reel_slip_deadband_ratio`；
  依据官服 1.04× 零磨损边界（单样本外推）。
- **速率重校**：tunable `reel_slip_calibration_seconds` 缺省 1.8 → 41.7
  （0.01% / 41.7s ≈ 0.00024%/s，对齐 W5 实测）。打滑速率不随过载比缩放
  （单样本无法辨识），取平坦值。轮油品质/适配倍率（0.8~1.2）保留为既有玩法层。
- **锁轮烧穿曲线删除**：官服无锁轮受力样本，`reel_locked_burn_base_s` /
  `reel_locked_burn_curve` / `reel_burn_calibration_drag_kg` 三个 tunable、
  `reelBurnSecondsFor`、发热曲线段状态（`SegSecs`/`BurnSecs`/`BurnWear`）与
  `reelOilBurnFactor` 全部移除。锁轮（29 档）之后走同一条打滑口径：线仍在
  泄力上出线就是打滑，按同一速率磨损，不再有"越锁越快烧穿"的独立曲线。
  "锁轮是赌一把"的玩法约束由断件判定（gear_damage 既有链路）承担，不在磨损层。
- **同原则停扣的无据通道**：电机（81）磨损停扣（官服无电轮数据，矩阵行保留
  全 0，聚合暂不计入电机寿命）、断件冲击（`perBreak`）与泡水（`perSoak`）停扣
  （官服数据只有受力时间与打滑），账本机械保留、矩阵置 0。
- 摩擦片按打滑小时数寿命约延长 ~23×：用户 2026-11-11 确认执行（单样本但为实测）。

### 6. 搏鱼中逐帧下发（官方表演对齐）

- `recordFightReelLoad` 每 tick 累加后，若耐久有变则节流 ~2s 做**中途落库**：
  取走账本 → `applyFightReelWear` → 立即重开新账，继承 `lastLoadAt`/
  `protectionChangedAt` 与承力缓存参数（烧穿曲线已删，无段状态要续）。
- **下发形状（抓包证据修正）**：官服搏鱼 4/22 帧是 args("61") **裸部件子树**
  （lure2 46 帧 + 底钓2 274 帧逐帧验证：轮件/竿件/旋钮/摩擦片/前导线作为独立
  对象并列，客户端按 GUID 原位更新）。实现为 `Push4_22Trees`（新增 Session 方法），
  发轮树全部子对象 + 竿树内 36/4/5 品类子对象；**绝不走全量 4/22**
  （`Push4_22Full`/`Push4_22Items` 的竿+线全树重建会重建鱼实体、打断冲刺/体力
  阶段，hFishingLoad 注释已验证）。
- **前导下发**：走既有背包物品通道 `Push4_22ItemGUIDs([前导GUID])`（官服裸前导线
  子树形状与我方子件类不一致，先用保守通道，实机验证后再对齐）。
- **损伤日志每竿仍一笔**：中途落库不写 `item_damage_log`，累计诊断字段
  （stress_seconds、各件磨损、slip 汇总）挂在账本上由最终结算一次写入。
- 写入频率：仅在 hooked 搏鱼期间每 ~2s 一次（轮、竿、前导各一行 fields/Durability
  UPDATE），量级与官服帧节奏一致，无表结构变更。

### 7. 数据与迁移 / 兼容 / 回滚

- 无表结构变更（子件耐久在竿 fields JSON，前导走既有 Durability 列）；迁移零。
- 协议侧：4/22 命令与 args code 不变，新增的下发形状（裸部件子树）以官服真实帧为据
  （46+274 帧逐帧验证）；客户端基线 4.0.25034 不受影响。
- 旧档兼容：轮/竿缺子件按满耐久（`reelChildDurability` 既有口径），首笔磨损才
  物化落库；无前导装配跳过。
- 回滚 = 还原矩阵字面量与三个校准 tunable（`reel_slip_calibration_seconds`、
  `reel_slip_deadband_ratio`、`wear_leader_per_stress_sec`）缺省值。行为开关一律
  不设：实机若发现下发形状有问题，修代码，不留运行时后门（2026-11-11 用户裁定）。
- 文档回填：`specs/capabilities/`（结算与装备契约）、`docs/mechanism-map.md`
  磨损入口、`docs/实测博鱼过程对装备磨损的影响分析.md` §7 状态行。

## Testing Decisions

- **单元（接缝 = `reelPartWearFor` / `fightReelTickWear`）**，期望值一律取抓包
  实测字面量，不用同码复算：
  - 17s 搏鱼窗口（n.pike）：轮油 Δ≈0.0066%、主齿轮 ≈0.0067%、导环 ≈0.0070%、
    轴承 ≈0.0024%、线杯 ≈0.0021%、竿坯 ≈0.0005%（±量级容差）。
  - 底钓2 回放：412s 搏鱼前导 Δ≈0.019%、导环 Δ≈0.104%（量级容差）。
  - 空竿回归：抛竿 + 92s 收线（只有 14/7、无 hook）→ 轮、竿、前导全部 Δ=0。
  - 旋钮（34）恒 1.0；钩无渐进磨损；电机通道行为不变。
  - 打滑：2.2× 过载 112s → 摩擦片 Δ≈0.027%；1.04× → 0；1.05× 以下全程 0。
- **存储（真实 SQLite）**：竿子件物化后二次快照耐久保持（rebuildRod 合并不丢）；
  中途落库 3 次后收竿结算 → 轮/竿/前导耐久连续、`item_damage_log` 每竿恰好一笔
  且汇总字段含 stress_seconds；同竿重放不重复扣。
- **行为（实机一次）**：一场搏鱼中 4/22 数字逐 ~2s 单调下行、结算后与下一场首帧
  连续；前导/导环磨损后强度与黄标按既有口径联动；过 `docs/client-checklist.md`
  装备回归项。
- **回滚变红**：还原矩阵/tunable 后上述速率与零磨损断言全部变红。

## Out of Scope

- 主线磨损通道（官服 4/22 搏鱼快照里没有主线，机制未知）。
- 钩（12）渐进磨损（官服实测 ≈0，现状断钩事件口径已一致）。
- 负载相关函数形式（线性/幂）与钓法间排序差异建模——量级带稳健、排序勿硬编码。
- 电轮电机（81）模型重设计（本方案仅停扣待数据）、竿本体耐久聚合。
- 强度字段（`nlmnpekipjc`）与 dur/workmanship 的换算式（分析文档未决 3）。
- "新件恒 1.0 是不磨损还是低于分辨率"的分辨（未决 4，需长会话抓包）。
