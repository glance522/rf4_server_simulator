## Problem Statement

两条抛投距离与官服手感脱节，且相互放大：

1. **淡水路亚标称过远**：castNominalLureM=45 是综合物理模型的 100% 基准，
   2026-11-13 实抓一根 UL 配置（1.8m 枪柄 + 水滴轮 + 3.33g 载荷）抛出
   40.85m（账本满力度口径），玩家随后纠正官服实际「只能 20~30 米」。
   模型其余因子（竿长/调性/线径/技能等）均自洽，问题只在乘法基准本身。
2. **红区超抛**：客户端功率条在满格红区可把 14/2 requested 推到服务端上限
   的 ~1.25~1.27 倍（同一杆 requested=51m / max 40.85m），服务端无条件
   采信（st.CastM = requestedM），玩家拉红区即白赚 25% 距离。官服拉满
   就是上限本身，不存在超抛。

## Solution

两刀，都不动修正器曲线：

1. **标称拆分**：castNominalLureM 45 → 27.5（淡水路亚 5-11/19/20/22；
   27.5 × 0.9077 实抓因子链 = 24.96m，落在官方手感带 20~30m 的中值）；
   海钓路亚（50-54，远投场景）新常量 castNominalMarineLureM=45 保留旧值
   待补锚点；浮钓/底钓/海钓底默认族 60 不动。
2. **红区收口**：14/2 落点快照改为 st.CastM = min(requestedM, actionMaxM)，
   仅带轮装配生效（actionMaxM = 158.f1 × 动作系数）；无轮手竿走旧协议
   基线（7.5m 不是真实上限），继续采信 requested。

依赖 cast-skill-wiring（PR #462）的 special_skill 因子：27.5 的锚点换算
含满级投距技能 ×1.6，必须在 #462 之上合入。

## User Stories

1. 作为玩家，我希望 UL 配置满功率抛 25m 上下，以便和官服手感一致。
2. 作为玩家，我把功率拉进红区时不再白赚距离——满竿就是上限。
3. 作为玩家，短促（0.92）/精准（0.86）动作的红区上限按动作系数同步收口。
4. 边界：无轮手竿不受收口影响（requested 直通，行为不变）。
5. 边界：request ≤ 上限时完全不动（正常区间零感知）。
6. 边界：海钓路亚（50-54）标称仍 45，待官服手感锚点后另立 spec 校准。

## Implementation Decisions

- 模块：`internal/gameserver`（cast_distance.go 常量 + castNominalDistanceM、
  handlers_game.go 14/2 快照）。无协议/迁移改动；158.f1（满力度上限）保持
  = profile.DistanceM，客户端功率条基准不变。
- `castNominalDistanceM`：lure family 内先判 marineRigType（50-54 → 45），
  其余路亚 → 27.5；family 外一律 60。55-60（海钓底/船竿）沿用默认。
- 收口点在 `st.CastM` 赋值处，不是 158.f1 也不是 14/2 响应：账本诊断日志
  仍记录原始 requested_m / max_m / power_ratio，收口动作单独一条 Info，
  便于事后统计红区频率。
- 动作系数进上限：actionMaxM = profile.DistanceM × castActionFactor(action)，
  与既有 powerRatio 口径一致（同一分母）。
- 收口只带轮装配生效：`profile.ReelGUID != ""` 是「走了综合物理模型」的
  精确判据（castDistanceForRig 无轮即返回 legacy 剖面）。手竿距离模型
  对齐（竿长×2）是 PR #457 的事，两支互不重叠。

## Testing Decisions

- 纯函数层（calculateCastDistance，手写期望带）：
  - 锚点复现：实抓 21:28 同参数（UL 配置 + mastery 95 + castPct 60）→
    期望 ~24.96m，断言带 [24.5, 25.4]；
  - 标称分族：castNominalDistanceM(5)=27.5、(52)=45、(1)/(12)=60；
  - TestCastCalibrationBands 区间整体 ×0.611（27.5/45）收紧；
  - 高阶装备上限测试改名重定标（45m 精准抛区间不再可达，新上限 ~29.7m）。
- handler 层（hCast，复用 TestCastSnapshotsRequestedDistance 接缝）：
  - 带轮装配 requested = 1.3×上限 → CastM == actionMaxM（收口生效）；
  - 无轮手竿 requested 50 > legacy 7.5 → CastM 仍 50（直通不变）。
- 回滚变红：标称回滚后锚点测试回到 ~40.85 变红；收口回滚后超抛用例
  CastM=65 变红。

## Out of Scope

- 海钓路亚（50-54）与浮钓/底钓默认 60 的官服手感校准：无锚点，等玩家
  实测口述，各自另立 spec。
- 客户端功率条红区行为本身（客户端二进制物理，改不了也不必改——服务端
  收口后红区只是无效输入）。
- 158.f1 的下发口径（客户端满格显示距离）：收口只影响落点快照，不动
  上限显示，避免客户端 UI 与服务端模型出现两套基准。
- 资格 5402（≥30m）与成就 1000-1004（30/45/60/80/100m）门槛是否随新
  动态范围重排：门槛数字是自标定，1004（>100m）在新标称下更不可达，
  属于「距离阶梯整体重设计」，另立 spec。
- 风力/姿势等新修正变量：模型扩展另有通道（RegisterCastDistanceModifier）。

## Further Notes

- [玩家口述] 2026-11-13：「其实只能 20-30米，如果我们取中间值 25的话」
  —— 针对实抓 UL 配置（1.8m 枪柄竿 bcr_6011 类 + 水滴轮 + 3.33g 载荷）
  抛 40.85/51m 的纠正。锚点取 25m 中值。
- [事实] 实抓 21:28:58 因子链（45 基准）：0.946(竿长1.8) × 0.990(Moderate)
  × 0.994(硬度2) × 0.866(3.33g/Test1-8) × 0.991(熟练95) × 1.600(技能
  708L7+717L5=+60%) × 0.945(线径0.28) × 1.030(延伸0.01) × 1.035(编织)
  × 0.999(线重) × 0.840(浅杯8) × 1.0(满杯) × 0.980(水滴轮) × 1.0(精力)
  × 0.857(轮效率) = 0.9077 → 40.85m；requested=51m = 1.248×上限（红区）。
- [推断] 27.5 = 25 / 0.9077：单一锚点定标。修正器链相对形状（技能/装备
  拉开的差距）全部保留，只平移乘法基准；27.5×0.9077=24.96 与锚点自洽。
- [事实] cast_action=0/2 的动作系数（0.92/0.86）与 powerRatio 同分母口径
  在 handlers_game.go 既有代码（actionMaxM）中已经成立，收口复用。
- [事实] 无轮手竿 legacy 基线（castBaseFloatM 7.5461488 / castBaseLureM
  7.1598907）是协议兼容位（float32 wire 原值），不是真实上限，快照直通
  是现状正确行为——收口若误伤会破坏浮钓短抛。
- [未验证] 海钓路亚 50-54 与默认族 60 的官服满功率手感；红区倍率是否随
  竿/轮变化（仅一组样本 1.248，收口与倍率无关，只影响诊断口径）。
