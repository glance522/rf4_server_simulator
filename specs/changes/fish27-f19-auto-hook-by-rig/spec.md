# 27.f19 自动上钩口径分钓法：沉底/海钓/路亚=1，浮钓=官方量级曲线

Status: in-progress

## Problem Statement

27 号判鱼对象的 f19 此前对所有钓法统一发鱼种/重量校准的连续小值（0.0006~0.01 量级）。
静置钓组可能长期不进入上钩状态，玩家收线或抬杆后才立即咬钩；实机把该字段固定为 1
后静置自动挂牢（曾以 PR #375 验证，上游未合入）。2026-11-11 官方服四钓法抓包证实
f19 的官方口径本就分钓法：并非全 1，也并非全曲线。

## Solution

- `buildFish27` 增加 `rigType` 参数，f19 分流：沉底/海钓/路亚族发**精确 1.0**；
  浮钓族保留按鱼种/重量校准的曲线值（官方量级）。
- tunable `float_f19_force_one` 非 0 时浮钓族也强制 1.0——浮钓静置不上钩的应急
  回滚开关，默认 0（官方口径）。
- 调用链 `pushPendingBite → pushBaitedFish → Push14_14 → buildFish27` 透传
  `st.RigType`；日志恢复路径与登录重推同链路自动生效。

## Evidence（2026-11-10/11 官方服抓包，脱敏：仅协议字段级数据）

11 个 14/14 逐帧解码 27 对象 f19（mgcgpgcjmil）：

| 钓法 | 样本 | f19 |
|---|---|---|
| 沉底 rig_type=24 | 丁鱥 | **1.0**（0x3f800000 精确值） |
| 海钓 rig 50+ | merlang 252g / piksha 2975g | **1.0 / 1.0** |
| 路亚 rig 5~11 | perch 93g / n.pike 4305g / b_gill 113g | **1.0 ×3** |
| 浮钓 rig_type=1 族 | taran 611g / c.roach 680g / crucian 293g / perch 119g、221g、342g | **0.00205 / 0.00243 / 0.00191 / 0.00102、0.00157、0.00213** |

- 浮钓 6 点为连续小值、随重量整体上行但非严格线性（含鱼种因素）；现有鱼种曲线
  （bream/c.carp/c.roach/crucian/e.chub/perch/s.bream 的 A·w^p）与官方量级吻合
  （perch/crucian 偏差约 -11%），保留即为官方口径的近似。
- `[事实]` 官方浮钓 f19≈0.002 时自动上钩仍 3/3 发生，14/14→14/11 时延
  +11.6/+4.44/+8.4s，明显长于其他钓法（+0.3~1.1s）；`[推断]` f19 是自动上钩
  尝试强度/速率输入，浮钓官方压低以保留看漂刺鱼玩法，自动钩只是兜底。
- `[事实]` 静置不上钩与 f19 低值相关：实机全钓法置 1 后手竿静置即可自动挂牢。

## User Stories

1. 作为手竿/海竿/路亚玩家，我希望静置钓组按客户端原生节奏自动挂牢，不需要先收线唤醒。
2. 作为浮钓玩家，我希望自动上钩节奏贴近官方（兜底而非必中），保留看漂刺鱼手感。
3. 边界：对象类型、字段 op、14/14 形状不变；不改咬钩延迟/发鱼权重/结算链。

## Implementation Decisions

- f19 曲线数据（fishStatics.f19 与 fallback 插值）保留不动，仅收窄使用范围到浮钓族。
- 开关命名 `float_f19_force_one` 与既有 tunables（marine_hook_confirm 等）同风格。

## Testing Decisions

- 合同测试 `TestFish27F19AutoHookByRigFamily`：rig 24/55/6 → f19=1（含回退鱼种）；
  rig 1 → 官方量级小值 (0, 0.01)。
- 实机验证：浮钓抛竿后不收线不抬杆，观察 3 分钟 ×2 轮——官方节奏下自动上钩仍应
  发生（约 4~11s 量级）；若浮钓静置不上钩，把 tunables `float_f19_force_one` 置 1
  应急恢复并另立 issue 排查浮漂信号路径。

## Out of Scope

- 不拟合官方浮钓 6 点的精确公式（样本不足，现有曲线已同量级）。
- 不动 14/9/14/11 分支的钩 4/22 推送（另案 PR #395 挂竿位全钓法）。
