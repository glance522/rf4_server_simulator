## Problem Statement

制作两个零材料配方可无限白嫖：

1. **切鱼块**（craft_bait_cut_fish → fish_pieces）：玩家在鱼护里选一尾鱼点制作，
   鱼块到手，但选中的鱼还在鱼护里——一尾鱼能反复切出无限鱼块。
2. **碎沸粒**（craft_crushed_boils → crushed_boils）：背包里选一粒沸粒打碎，
   碎沸粒到手，沸粒一粒不少——无限碎沸粒。

根因：静态库 recipe 表这两个配方的 materials_json='[]'，hCraft 的扣料分支
（引线/贩卖机/显式需求+鱼护兜底）全部不触发。上游 PR #175 已知零材料配方
不扣料，只把份数钳到 1（每次白嫖 1 份），没有接消耗。2026-11-13 实机白嫖
两次（切鱼 took=0、碎沸粒 took=0，日志实锤）。

## Solution

这两个配方的材料改由客户端材料槽直接定位并真实消耗：切鱼槽的 guid 是
鱼护 echo guid，碎沸粒槽的 guid 是背包沸粒实例 guid——客户端本来就把
选中实例发上来了（实抓 2026-11-13 两次 9/1 报文），服务端此前只是无视。
材料缺失/已被消耗/鱼种不符时整体 803(false)，不产物不扣料；同请求里的
工具槽（切鱼刀、研磨机）是可复用工具，不消耗。

## User Stories

1. 作为玩家，我希望切一条鱼后鱼护里那条鱼真的消失，以便鱼块有真实成本。
2. 作为玩家，我希望打碎一粒沸粒后背包里那粒沸粒真的扣掉。
3. 作为玩家，我希望切大鱼出的鱼块比切小鱼多（官服产量按鱼重阶梯），
   以便钓到大鱼时切鱼更划算。
4. 边界：材料槽缺失或指向已消耗的实例时，制作失败（803 false），什么都不产出。
5. 边界：切鱼时材料槽带的鱼种与鱼护条目不符（陈旧槽位）时拒绝，不删错鱼。
6. 边界：qty 传 1000 仍只产出 1 套（沿用既有零材料钳制）。
7. 边界：整堆只剩 1 粒沸粒时扣光删行，产物照常入库。

## Implementation Decisions

- 模块：仅 `internal/gameserver`（craft_ops.go）。无协议/表结构/迁移改动。
- `slotConsumableForRecipe(recipeID)`：配方 → 可消耗材料槽需求 id 的映射
  （craft_bait_cut_fish → bait_fishForCut；craft_crushed_boils → craft_mat_boil）。
  其余零材料配方（52 个标本板/奖座族）返回空，继续走既有标本挂鱼路径
  （mountedFishTreeTx 同事务消耗渔获），行为不变。
- hCraft 消耗链新增分支（排在三个既有扣料分支之后）：按需求 id 找材料槽，
  - 切鱼：槽 guid = 鱼护 echo guid → 事务内查条目（KeepnetListTx）、鱼种
    容错校验（槽带鱼种且两边都非空时必须一致）、consumeKeepnetEntryTx
    （删条目+镜像行/槽位，与标本挂鱼同一语义）；keepnetTaken 收集，
    AfterResponse 统一推 4/21 让客户端鱼护界面撤下原鱼。产量按鱼重阶梯
    （`cutFishPiecesForWeightG`：整公斤每公斤 1 块、不足 1 公斤 1 块），
    经 `rewriteCraftOutputQty` 覆盖 prepareNewItem 按定义单位量的折算
    （fish_pieces 单位量 30，按单位折会一刀 30 块），数量槽与 row.Qty 同步。
  - 碎沸粒：槽 guid = 背包/钓组沸粒实例 → consumeItemQtyTx 每套扣 25
    （官服语义 25 粒磨 1 份；部分扣改堆数量，扣光删行，不足整体失败回滚）。
  - 两者的消耗都在经济事务内，失败整体回滚，杜绝"产物已入库、材料还在"。
- 不按品类兜底扣料：碎沸粒输入是 HVZ 沸粒（boils_hvz_*，cat27），同品类的
  拟饵/颗粒/老虎坚果不能误吞，必须按槽 guid 精确扣。
- 兼容：客户端基线 4.0.25034，槽形来自实抓报文；无迁移，回滚即还原为
  零消耗行为（上游 #175 口径）。

## Testing Decisions

- 行为层（handler 级，复用 economyTestCtx + craftObj8 槽形接缝）：
  - 切鱼成功：鱼护条目消失、fish_pieces 恰 1 块（1200g 鱼）；
  - 切鱼产量按重阶梯：3400g→3 块 + 700g→1 块，共 4 块（手写常量）；
  - 切鱼缺槽/鱼种不符：803 false、不产物、鱼护原样；
  - 切鱼带工具槽：切鱼刀不消耗；
  - 碎沸粒成功：150 粒扣 25 剩 125、研磨机不消耗；
  - 碎沸粒不足 25 粒失败：30 粒磨一次剩 5，第二次失败回滚仍剩 5；
  - 碎沸粒沸粒不存在：803 false、不产物。
  - 期望值全部为手写常量（种子数、剩余数），不回算。
- 既有回归：craft_limits_test「零材料配方限制1份」子测试从"无槽免费成功"
  改为"带槽成功 + 材料真实消耗 + qty=1000 钳 1 套"；蟹肉/活饵/鱼片族
  （显式需求+鱼护兜底路径）保持全绿。
- 回滚后变红：切鱼/碎沸粒的成功+扣料用例回滚后必然变红（回到零消耗）；
  产量改写回滚后 1200g→30 块，恰好 1 块的断言变红。

## Out of Scope

- 工具耐久消耗（切鱼刀/研磨机是否掉耐久）：无官服样本，工具 universally
  不掉耐久是本仓现状。
- 其余零材料配方的标本板族渔获消耗：已由标本挂鱼路径正确处理，不动。
- 静态库 recipe 表补 materials_json：材料是"玩家选中的那一尾/那一粒"，
  数据面表达不了槽位指向语义；且静态库只读、由 seed 替换。
- 上游 356 个有材料配方的核对：既有路径有测试覆盖，无证据表明有问题。

## Further Notes

- [事实] 2026-11-13 实机抓包：切鱼槽 = {bait_fishForCut, 鱼护 echo guid
  b5e94a02…, "s.orfe"}，碎沸粒槽 = {craft_mat_boil, 背包沸粒实例 guid
  6d088bb6…, "boils_hvz_van12"}；两次制作日志均 took=0，鱼/沸粒均未扣。
- [事实] 碎沸粒需求 id 是 craft_mat_boil（14 字符）：wire 长度前缀 0x0e=14，
  紧跟的 6d('m') 是 guid 首字节。首版解码误拼成 craft_mat_boilm，上线后
  4/4 失败「材料槽缺少选中材料」（2026-11-13 20:18 日志），按前缀长度重对
  齐修复；玩家背包沸粒 guid 6d088bb66c11b27c3806d9a6bf46d702 与槽逐字节
  一致，佐证切分。
- [事实] 静态库 recipe 表 craft_bait_cut_fish 与 craft_crushed_boils 的
  materials_json 均为 '[]'；零材料配方共 54 个，其余 52 个为标本板/奖座
  （输出 cat71，走标本挂鱼消耗路径）。
- [事实] boils_hvz_*（HVZ 沸粒）与 boil_*（六色香煮成饵）同为 cat27；
  crush 工具槽实抓为 craft_tool_crusher/hvz_b_grinder（饵料研磨机）。
- [事实] 官服切鱼产量随鱼重阶梯，不固定：社区实测 512g 草鲤→1 块、
  2kg 以上→2 块、3.4kg→3 块、3.8~3.9kg→3 块（4 尾 3.4~3.9kg 共 12 块，
  42+12=54 的库存算术吻合）。来源（2026-11-13 检索）：
  https://steamcommunity.com/app/766570/discussions/9/766311764554189508/
  https://www.reddit.com/r/Russian_Fishing_4/comments/1meh0pq/making_cutbait_pieces
  另有失败制作也耗鱼（官服失败即扣料，本仓失败整体回滚，语义更保守，不改）。
- [推断] 阶梯公式取"整公斤每公斤 1 块、不足 1 公斤 1 块"（max(1, ⌊kg⌋)）：
  唯一同时满足上述四个样本点的整公斤阶梯；2 块的精确下限（0.5~2kg 之间）
  与 4 块门槛社区无定论，客户端配方库为编译进二进制的资源提不出来
  （见碎沸粒证据），故按最小阶梯实现，待实机核对后收紧。
- [推断] "1 条鱼 → 1 次切鱼" 与客户端每次只让选一个实例、配方
  output_qty=1 一致（产量不再按定义单位量折件——折算会一刀 30 块）。
- [事实] 碎沸粒官服语义 25 粒沸粒磨 1 份：2026-11-13 实机制作界面显示
  25 粒/份（玩家口述）；首版误按 1 粒/份实现，玩家当场指出（"不是 25 粒
  制成一份吗"）。客户端配方库为编译进二进制的资源（resources.assets 只有
  文案块，GameAssembly/Managed/globalgamemanagers 均无配方明文数量），
  无法从资源逐字提取，数量锚定实机 UI。
- [未验证] 官服工具是否掉耐久；切鱼阶梯的精确门槛（2 块下限、4 块起点）。
