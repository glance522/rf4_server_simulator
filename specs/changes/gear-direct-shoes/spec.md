# 钓具助手快捷开关与五速鞋

Status: in-progress

## Problem Statement

玩家进入钓具助手子菜单后，完整功能指令被当前菜单吞掉；同时希望通过同一个联系人保存并控制跑步加速。

## Solution

直接发送“满红不爆 开/关”“耐力 开/关”“五速鞋 开/关”即可切换，旧数字菜单保留。五速鞋默认关闭，需要可选客户端模块；开启后跑步为原来的三倍，走路不变。

## User Stories

1. 在任意子菜单发送完整功能名和开关，修改指定功能并进入其子菜单；只发名称沿用原状态查询与子菜单。
2. 五速鞋按玩家保存，重复开启不累计倍率，不影响满红不爆和耐力播报。
3. 重登后静默恢复设置，手动查询正常显示；不安装客户端模块的玩家移动速度不变。

## Implementation Decisions

- gear_assistant.go复用既有kv、邮件与事务，新增shoes键，无表结构迁移；保留上游满红不爆与耐力播报语义。
- 菜单排版、功能说明、状态查询和操作回执沿用原有gearAssistantHelp、gearSubShow和gearReply，只在功能表中增加五速鞋；普通回复不附带同步字段。
- 开关变更由客户端读取现有五速鞋操作回执。重登恢复另用现有19/10、Args524和buildMail11062；proto.ps1 class hoabkabpoom确认其类型为11062/MailboxMessageMeta，不新增wire类型或修改字段。
- 自动同步回复与已读标记同事务提交后推送；客户端仅接受当前账户、正确发送者和元数据类的回执与同步快照，并用递增邮件ID拒绝旧设置。
- 可选客户端模块独立初始化IL2CPP、会话和移动方法，不依赖远程设施或抄网。只临时替换_runSpeed，调用原移动方法后恢复。
- 后台初始化等待核心程序集就绪，注册线程后才枚举程序集和读取元数据，完成或退出时注销该线程；日志默认写入用户可写临时目录。
- 客户端不改写任何普通聊天消息或托管文本引用，只消费启动时显式请求的静默同步响应。
- 客户端基线4.0.25034；关闭模块后重启客户端可恢复，服务端旧设置可保留。

## Testing Decisions

- 复用现有真实SQLite与协议回环接缝，覆盖跨子菜单完整命令、异常参数、默认关闭、重复开启、账户隔离、静默同步已读及不改变菜单。
- 构建服务端及独立原生模块，检查贡献文件中没有鱼过滤、远程设施、抄网和本机配置。
- 提交前记录实际执行的检查；独立桥接的实机验收与已有个人模块的历史验收分开报告。

## Out of Scope

不增加鱼过滤、大抄网、远程设施、倍率或回放，不修改装备损坏、体力、物品和发鱼规则。
