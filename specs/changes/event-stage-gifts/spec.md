# 活动阶段礼物（阶段奖励）

Status: done

## Problem Statement

新年/周年活动面板的每个阶段承诺"完成一个阶段可获得礼物"，但服务端从不下发
阶段奖励：面板阶段下没有任何奖励预览行，完成任务也没有任何物品到账。
玩家只能看到任务进度，奖励承诺完全是空的。

## Solution

管理员在 Control Deck 配置每个活动分支每个阶段的奖励物品与数量后：
面板阶段下出现对应的奖励预览行（物品图标、名称、详情入口）；
阶段内全部可见任务完成时，奖励物品真实入账，且重放、重连、重复巡检都不会重复发放。

## User Stories

1. 作为管理员，我希望按分支/阶段配置奖励物品与数量，以便活动奖励可维护。
2. 作为玩家，我希望在面板上看到阶段奖励预览，以便知道完成阶段能得什么。
3. 作为玩家，我希望阶段完成时奖励真实到账并可从背包取用。
4. 边界：同一请求重放、断线重连、重复巡检不重发；缺口任务（面板上不可见）
   不阻塞阶段达标；未配置奖励的阶段保持现状（无预览行、无发放）。

## Implementation Decisions

- 预览下发：5008.f2（阶段奖励预览键，`proto.ps1 class goglkgnhpcl`）。
  编码为 0x04 数组（u16 数量 + 每元素 u32 长度 + 原始 UTF8 目录键），
  与 1/5 配置版本响应的字符串数组同型；重复键客户端去重，数组不表达数量。
- 配置源：tunable `event_stage_gifts`（JSON：分支 → 阶段 → 物品/数量），
  经 Control Deck 既有 tunables 通道热更；管理后台「游戏参数 → 限时活动」提供
  按分支/阶段/物品数量维护的结构化编辑器，奖励选择器先按分类读取完整静态目录，再按分类读取商品；活动专属商品即使没有 `shop_item` 货架记录也可选，按商品分类分组并排除竿坯、手柄、线轴和渔轮内部件，保存格式仍为该 JSON；预览随下一次
  游戏客户端重启后的 28/1（客户端重新登录）生效，发放判定按最新配置。管理 API 同时校验 JSON 形状、
  分支范围、阶段范围和数量范围。
- 达标口径：分支阶段内**已下发（非缺口）任务**全部完成，与分支奖杯口径一致；
  缺口任务（`eventGapRuleIDs`）不阻塞。
- 发放：复用分支奖杯的 kv 幂等模式（`event-stage-gift:<uid>:<branch>:<stage>`），
  物品构造 + 幂等键 + 入账同一经济事务；数量用 `prepareNewItemWithCount`，
  可堆叠物品合并（`grantPreparedItemTx` merge）。
- 挂接点：与 `ensureQualificationCups` 相同——14/4 结算后与 28/2 全量快照。
  与奖杯相同的兜底口径：首次巡检对已达标但未标记的阶段补发，覆盖上线前历史进度。
  新发物品按普通背包物品树推 4/22，合并一条系统聊天播报。
  14/4 结算同时携带奖励物品树和 801.f4 礼物行；合并礼物行时保持
  args(173) 内直接包含 811 对象，避免嵌套数组造成客户端解码失败。
- 范围：仅活动分支 9..20（主资格分支 1..8 阶段不发礼物，杯已有）。
- 迁移：无新表（复用 kv 幂等键与既有物品表）。
- 兼容：客户端基线 4.0.25034。回滚 = 移除发放挂接点与预览填充；
  f2 未配置时保持现状 null（`[事实]` null 现状长期实机稳定；空 0x04 数组行为未验证，
  不冒进）。

## Testing Decisions

- 单元（纯逻辑）：配置解析与校验（非法 JSON、未知分支/阶段、qty≤0、空键）；
  预览构造（有配置 → 0x04 数组且键序去重正确；无配置 → null）。
- 管理端：结构化编辑器能从现有 tunable 还原阶段奖励，保存为预期 JSON，
  并在 1280px / 360px 视口下保持控件可操作。
- 行为（真实 SQLite，复用 `qualification_rewards_test.go` 的预填接缝）：
  阶段差一条任务不发放 → 补齐后恰好发放一次、数量正确 → 重复巡检/重复预填不重发。
- 快照补发：验证 28/2 触发的 4/22 推送满足协议契约，奖励使用普通背包容器，
  重复快照不再推送奖励；验证 801.f4 合并后直接包含 811 礼物行。
- 期望值来自手算样例与静态 item_def 已知条目（fcb_coffee_can2 / ab_tea_can2），
  不用实现代码反推。
- 回滚后：上述行为测试变红（发放与预览函数被删即编译失败）。

## Out of Scope

- 任务组奖励、全部任务完成奖励、任务模板后台维护、草稿/发布/版本化。
- 会员资格判定与过期边界。

## Further Notes

- `[事实]` 5008.f2 编码与预览渲染：实机验证（客户端 4.0.25034，2026-11-13）——
  args(524) 编码抛 `InvalidCastException: Object → String[]`（`goglkgnhpcl.plphdfehkjl`）
  并断线；0x04 数组编码在资格面板正确渲染咖啡/茶奖励行（图标、名称、详情入口），
  重复键去重。
- `[事实]` 28/1 内容树只在客户端进程首次登录时拉取，重登不刷新（实机验证）。
- `[事实]` 资格面板与新年活动面板都会渲染 f2 预览行（2026-11-13 实机验收：
  活动面板 MMXXV 阶段 1 出现咖啡/茶奖励行）。此前"活动面板不渲染"的观察
  是内容树陈旧所致——28/1 只在客户端进程首次登录拉取，面板数据不会热更新。
- `[未验证]` 空的 0x04 f2 数组在客户端的表现。
