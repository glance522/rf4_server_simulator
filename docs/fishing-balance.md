# 装备与鱼类匹配

装备规格取当前静态定义及实际装配，鱼种和自然重量窗口取现有水域、饵效、鱼种重量表。模型、动画、碰撞和游动由客户端负责；服务端发送鱼种、实际重量、体长、体力及搏鱼曲线。

## 承力与力度条输入

- 竿、主线、前导、连接件、鱼钩和锁轮承力统一按 kgf 比较最弱环；组合前导取内线与连接件的较小值。
- `reel_locked_loads.json` 保存玩家提供的锁轮拉力表中能唯一对应当前静态定义的 544 款型号。未对应的 3 条记录不套用；未收录的型号沿用原估算。
- 刹车片决定泄力，轮体决定锁轮承力。更换刹车片不会把轮体承力一起抬高；耐久阶段、轴承与润滑磨损沿用现有规则。
- 鱼的协议拉力以牛顿表示，最弱件承力以 kgf 表示；换算使用已有小鱼校准比例。日志、鱼对象及曲线由同一拉力函数生成。
- 力度条由客户端渲染。协议数值一致不代表力度条颜色、物理判定和现场手感已经实测一致。

## 鱼的力量、体力与派鱼

1 kg 以下保持质量的线性关系；更大个体按各类自己的力量和体力增长指数计算，避免大鱼只按统一倍率放大。

| 类别 | 力量系数 | 体力系数 | 力量指数 | 体力指数 | 无专属曲线时的运动模板 |
| --- | ---: | ---: | ---: | ---: | --- |
| 普通及未知鱼种 | 1 | 1 | 2/3 | 0.75 | 原有兜底 |
| 鲤类 | 1.1 | 1.35 | 2/3 | 0.78 | 鲤类 |
| 鲑鳟及哲罗鱼 | 1.25 | 1.5 | 0.70 | 0.80 | 雅罗鱼的活跃模板 |
| 鲟类、大型鲶类 | 1.15 | 1.8 | 0.64 | 0.82 | 鲤类 |
| 金枪鱼、剑鱼、鼠鲨 | 1.5 | 2 | 0.70 | 0.80 | 活跃模板 |
| 姥鲨、格陵兰鲨 | 1.1 | 2 | 0.64 | 0.80 | 鲤类 |
| 大型底栖海鱼 | 1.05 | 1.35 | 0.65 | 0.80 | 鲤类 |
| 狗鱼、梭鲈、部分鲈类 | 1.15 | 1.2 | 0.68 | 0.73 | 鲈类 |

这些系数和模板适配是本地玩法设定，不是生物学测得的拉力或体力值。已有专属曲线优先使用；冲刺阶段时间、相对张力、重复次数及动作参数沿用已有曲线，不另造运动协议。

派鱼按鱼种力量反推重量窗口，同时保留原有 35% 操作余量和钩体尺寸限制。鱼种仍须符合水域及饵规则；在可用窗口内采样自然分布，不把超限鱼统一裁成极限重量。所选鱼种完全不匹配时换试同一名册内的其他候选；整组无候选则空竿，不补发其他水域的鱼。

`fish_weight_scale` 在判档、体长和承力检查前生效；`fight_power_scale` 同时影响拉力、曲线和匹配窗口。大鱼不会因为增重预设绕过装备限制。`fish_stamina_scale` 及初始体力设置继续生效，实际体力扣减和疲劳阶段由客户端执行。

## 函数拟真分析

`analyzeFishFight` 使用与发鱼相同的力量、体力及曲线输入，输出基础拉力、曲线潜在峰值、初始体力、每单位拉力对应的体力和装备余量。每次成功派鱼记录一次分析结果，便于对比小鱼、大鱼、巨物及混搭装备。

- 基础负载比：`F / (g × B)`；峰值负载比：`F_peak / (g × B)`，其中 `B` 为最弱件 kgf，`g` 使用已有校准换算。
- 初始体力：`S × 初始体力比例`；相对耐力指标：`初始体力 / F`。同一鱼只换装备时，鱼自身的力量和体力不变。
- 峰值取所选曲线中张力字段相对基础行的最大比例。曲线发送和分析共用同一模板选择入口。

分析会加入下述冲击缓冲和水流负荷，默认场景仍按锁轮计算。它不是客户端实测的力度条百分比或断件概率。体力池不是已标定的焦耳量，不能用该比例宣称精确遛鱼秒数；速度和碰撞运行逻辑未确认前不推算逃窜距离。

## 联合计算链

| 输入 | 进入的计算 | 约束 |
| --- | --- | --- |
| 鱼种、重量、体长 | 分鱼类力量与体力函数、迎流面积 | 同一条鱼不因换竿改变自身力量 |
| 竿的额定承力、耐久、长度、锥度 | 最弱件、瞬间冲击缓冲 | 缓冲不提高额定承力 |
| 主线的材质、直径、伸长、密度、剩余长度 | 沿用抛投材料参数、冲击缓冲、线受流面积、放线边界 | 剩余长度为零不能恢复成整盘长度 |
| 轮体、摩擦片、轴承、润滑与磨损 | 锁轮承力、可调泄力与抛投性能 | 刹车片升级不提高轮体额定承力 |
| 前导、连接件、钩与制作材料 | 真实实例的最弱环、断件与同步 | 不从空制作模板臆造材料强度 |
| 钓法、竿型、实际装配 | 复用现有允许矩阵、钓组、钓深和抛投管线 | 不另设一个修改鱼能力的钓法倍率 |
| 水域、流速、流向、水深与鱼深 | 环境受力、匹配预算、深度与线长边界 | 未知地形不伪装成测得水深 |

目录验证遍历 4364 条承力类定义，并核对其中所有可购买型号；52 种制作前导逐配方实际扣料及保存成品。未上架且没有承力数据的占位型号不补造数值。拟饵及其它制作产物沿用既有定义物化，其出厂钩进入同一最弱件计算。

已知部件耐久归零会阻止匹配，不能按“没有强度资料”跳过后改用其它部件的承力；前导内嵌材料归零也不能在读取时恢复成新件。

力量函数为 `F = g × a × M(w,p) / 1000`，其中 `w` 为克、`a` 为鱼类力量系数；`M=w`（不超过 1 kg），否则 `M=1000×(w/1000)^p`。体力使用同样的连续增长形式，但有独立的系数和指数。鱼类专属搏鱼曲线给出相对峰值。

稳态负荷保留，增量冲击乘以 `b=(1−0.5×线伸长率)×竿缓冲系数`；竿的长度和锥度最多再缓冲 15% 的增量冲击。这是本地平衡近似，不是本体反编译得到的材料定律。线直径及密度不再额外编造强度倍率；它们分别影响受流面积及运行线段质量，额定强度仍取装备定义。

显式场景分析可以提供泄力比例和已放线长：尚有余线时，传递负荷受到实际摩擦片泄力约束；达到存线末端后失去继续放线的保护。手竿没有渔轮泄力。此函数不自行假定玩家实时旋钮位置或每帧出线速度。

制作前导保存所选线/钢丝及连接件的子实例，沿用材料自己的磨损，再取材料最小承力与成品耐久。批量制作独立成品；扣料、成品及流水在同一事务中完成。旧的空材料成品不能还原来源，拒绝重新挂载及正常派鱼，需要重新制作。完整物品同步沿用 `4/22` 的现有容器，将竿、轮、线、前导、连接件和钩的当前属性一起发给客户端。

## 水域、洋流方向和钓法

水流负荷采用 `D=0.5×ρ×v²×(Cd×A鱼+1.2×d线×水下线长)`。鱼面积以近中性浮力椭球近似，体积为质量除以 1050 kg/m³，迎流面积为 `1.5×体积/体长`。鱼形系数按类别取 0.2、0.35 或 0.45；它们是待实机标定的游戏近似，不能当作各鱼种测量值，也不是渲染或碰撞体积。

方向采用同一水平坐标系内的流向角和拉拽方向角。平行分量为 `D×cosθ`，横向分量为 `D×sinθ`，合力为 `hypot(max(0,F+D平行),D横向)`。顺着拉拽方向增加负荷、逆向可卸载、横流产生侧向负荷；方向缺失时按加重负荷估计，不编造世界方向。匹配时不依赖逆流暂时带来的卸载，保留转向余量。该静态模型只处理给定流速的环境分量，尚无鱼速遥测，不能声称已求解完整相对游速或三维水动力。

预设按地图水域类型选择：水塘 0、湖泊 0.05、河流 0.35、激流 1、回湾 0.1、海水 0.25 m/s；淡水密度取 1000、海水取 1025 kg/m³。这些流速是可覆盖的玩法预设，不是本体流场的实测值。地图默认不猜水深，不自动把整条河判成激流或回湾。

通过已有运行参数 API 的 `fight_water_profiles` JSON 字符串覆盖；优先级为地图、地点、`地点:钓点编号`。支持 `kind`、`current_mps`、`density_kg_m3`、`water_depth_m`、`fish_depth_m`、`current_bearing_deg`、`pull_bearing_deg`。角度表示流动/拉拽朝向，使用同一坐标系；没有实时方向报告时只能使用明确配置的场景角度。示例：

```json
{
  "level_008_sura_river": {"kind":"river","current_mps":0.4},
  "loc_test:42": {"kind":"backwater","current_mps":0.1,"water_depth_m":8,"fish_depth_m":3,"current_bearing_deg":90,"pull_bearing_deg":0}
}
```

浮钓仅用设定钓深估计初始鱼水层，不把它当成水底测量；底钓及垂直海钓在配置了水深时使用该深度，路亚不虚构固定水层。鱼深超出已知水深或剩余线长时不匹配。海水与淡水通过密度参与受流计算；静水压力 `ρgh` 只作诊断，不能直接加到钓线张力上。鱼的真实下潜轨迹、河岸回湾边界和海底障碍仍由客户端场景运行。

水流和冲击与鱼拉力共用最弱件预算，数值求解匹配上界。环境力不重复写进鱼对象的固有拉力，避免与客户端原有水流物理叠加。相对耐力指标考虑场景合力，但实际体力扣减仍是客户端执行，尚未标定流速对应的每秒疲劳。

## 体型校准与巨物

`fish_body_lengths.json` 提取[公开鱼体型校准页](https://ai.055510.xyz/uploads/rf4.html)的 57 组数值，仅替换通用体长兜底系数；已有鱼种专属长度公式和历史鱼获保持原值。页面中的样本重量是校准点，不是最大重量。

| 鱼种 | 当前蓝冠线 | 按蓝冠线×1.25的采样上界 | 校准公式下的上界体长 |
| --- | ---: | ---: | ---: |
| 姥鲨 | 2500 kg | 3125 kg | 8.03 m |
| 格陵兰鲨 | 900 kg | 1125 kg | 6.60 m |
| 蓝鳍金枪鱼 | 400 kg | 500 kg | 3.21 m |
| 剑鱼 | 450 kg | 562.5 kg | 4.23 m |

这些上界来自当前游戏采样规则，不是生物学最大纪录。格陵兰鲨超大型历史报告存在不确定性，不能拿未经确认的长度作为硬性碰撞边界。钩体入口约束继续按钩长立方增长，去掉人为的统一 2000 kg 截止，最终仍必须满足钓组承力与鱼种自然分布。

2000 kg 姥鲨的验证场景中，校准体长约 6.92 m、基础拉力约 1398 N；现有 238.392 kgf 竿、205 kgf 主线、181 kgf 前导、205 kgf 锁轮及大钩，在 0.25 m/s 海流和 100 m 鱼深下仍有匹配窗口。5 kgf 主线会拒绝同一条鱼。这个例子验证函数及部件边界，不证明实机已能在固定时间内钓起巨物。

## 断件与存档

派鱼和超载处理共用最弱环排序。主线断仍只扣原规则的 5 米，耗尽的线不会恢复默认盘长。断钩保留竿、轮、主线、前导、浮漂及其他钩；多钩组只移除能确定对应关系的饵。拟饵出厂钩按自身耐久计算，断钩后保留拟饵及剩余钩。终端件移除、钓组索引、物品树和客户端响应一起更新。

待结算鱼的 JSON 增加可选的 `force`、`stamina`，保存显式指定值并在重启恢复。旧 JSON 缺字段时仍为零并按原有兜底入口计算，不改数据库表结构，也不改历史鱼获。

## 本体与公开资料的边界

适配客户端为 4.0.25034。对本地资源的只读检查找到 `FishFamilyAsset` 的小、中、大模型引用，`FishAsset` 的长度轴、长度系数和包围盒选项，以及 749 个鱼类胶囊碰撞体。样本中白鲟小/中模型胶囊高度为 0.75、大模型为 0.82；大型金枪鱼为 0.75。这些是模型基准坐标，不能当作真实鱼长或最大体型，也不能据此声称已还原运行时缩放和碰撞公式。

`RodAsset`、`ReelAsset` 包含挂点、卷线、缩放和动画配置；承力仍从已有静态物品属性及锁轮资料读取，不把模型尺寸当作强度。客户端资源、模型和提取文件不随源码分发。

地图只读检查另找到 `FlowDirectionAndSpeed`、`FlowSpline`、`SplinePointDataFlow`、`WaterBounds`、`FishingLineTension` 及 `FishFightBreakCondition` 的类型线索。多个河流和海洋场景存在流向/速度组件；场景脚本的字段类型树已裁剪，不能可靠解释剩余二进制字段的单位和坐标，也不将渲染流场直接认作钓组物理流场。因此没有把猜测的原始浮点数导入水域配置。

公开资料用于核对鱼类身份、体型与习性，而不直接替换游戏参数：

- [NOAA：大西洋鲑](https://www.fisheries.noaa.gov/species/atlantic-salmon)：洄游及体型资料。
- [NOAA：金枪鱼](https://www.fisheries.noaa.gov/feature-story/fun-facts-about-atlantic-tunas)：体型、流线外形和游泳特征。
- [NOAA：大西洋鲟](https://www.fisheries.noaa.gov/species/atlantic-sturgeon)：底栖觅食与大型体型；不用于替代白鲟的种级数据。
- [FAO：鲤](https://www.fao.org/fishery/docs/CDrom/aquaculture/I1129m/file/en/en_commoncarp.htm)：形态与生活习性。
- [NOAA：姥鲨识别](https://www.fisheries.noaa.gov/new-england-mid-atlantic/atlantic-highly-migratory-species/shark-identification-cooperative-shark)：核对 `cetorhinus_m` 对应的鱼类及大型体型。
- [捕获对大型远洋鱼的生理影响研究](https://www.mass.gov/doc/evaluating-the-physiological-and-physical-consequences-of-capture-on-post-release-survivorship-in-large-pelagic-fishes/download)：捕获挣扎涉及疲劳及生理恢复，不能等同于固定游戏秒数。
- [NASA：阻力方程](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/drag-equation/)：密度、相对速度平方、面积与阻力系数的关系；不提供鱼形系数。
- [NOAA：深度与压力](https://oceanservice.noaa.gov/facts/pressure.html)：静水压力随深度增加；不等于作用于钓线的净拉力。
- [NOAA：北太平洋剑鱼](https://www.fisheries.noaa.gov/species/north-pacific-swordfish)：公开体型量级对照。
- [FAO：格陵兰鲨资料](https://www.fao.org/4/ag419e/ag419e05.pdf)：成年体型及更大历史报告，保留其不确定性。

尚未从所检查的本体资源证实各鱼种的硬性最大重量、真实三维体积、疲劳扣减公式和逃窜距离边界。服务端验证了配置深度、剩余线长、材料及承力边界；运行时地形碰撞、动态放线、力度条颜色及遛鱼时长仍需客户端实测。
