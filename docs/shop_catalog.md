# 商店目录

商店货架会按 `store_id`，根据内置商店定义和静态 `shop_item` 目录解析。内置定义保存在 `internal/store/assets/shop_kind_defs.json`，覆盖七种商店类型中的 205 家商店。

## 解析顺序

对于已知商店，基础货架按以下顺序选择：

1. `shop_item` 中该商店对应的行。
2. 同一商店类型和品牌组合下，其他商店对应的行。
3. 该商店类型的共享模板。
4. 没有可用定义或行时，使用空货架。

未知的 `store_id` 会返回空货架。已知商店按现有品类补齐商品，品牌店同时限制为同品牌；装配零件不单独上架。已有定价沿用原币种，无价商品按上游同系列最高价或同类中位价估价，并按商品编号稳定上浮 0–10%。

补齐基础货架后，会按 `(store_id, item_id)` 应用 `shop_item_override`。该配置可以分别覆盖银币价格、金币价格和库存。覆盖配置仅作用于对应商店。银币与金币商品持续供货，生效库存为 0 时自动补至 1000；刷新和重启不会修改价格、余额或背包。

商店浏览、购买结算和管理 API 使用相同的解析路径，因此展示价格与结算价格保持一致。

## 覆盖范围

内置定义为七种商店类型提供共享货架模板。类型 2（工坊，18 家商店）和类型 8（导览与租赁，3 家商店）没有基础模板；除非添加商店专属的 `shop_item` 行，否则这些商店保持空货架。

如需修改基础货架，请更新 `server_data/static.sqlite3` 中的静态目录，并重新运行 `seed`。存储层会拒绝运行时对静态表的写入。

## 管理功能

控制台可以覆盖货架上已有物品的价格和库存。移除覆盖配置会恢复基础值。补齐商品也可设置或移除覆盖；不属于该店品类或品牌的物品仍不能通过覆盖强行上架。
