  - 100~105（等待期小动作）；300/301/302/304/305/306/309（搏鱼期：301 窜逃 / 302 下潜外冲 / 306 持续拉扯等）

## 三、客户端断线判定（"脱钩"的真实机制）【实证】

判定方：**客户端本地**。服务器被动确认（模拟器日志原文"17/9 按客户端上报断件"）。

### 判定链（FishingSet.cs:1652 dncjeoomgco，每帧）
1. 门控：渔具状态 ∈ {2 搏鱼挂鱼, 3 收线} 且 线绷紧度 `fjamjbjmfdd() > 0.5`
2. 鱼拉力 F = `faioflmebgi()`（牛顿，客户端本地鱼物理：外冲拉力来自 f21 曲线池随机抽取）
3. 逐部件算承力上限，取**最小的那件**：
   - 线/子线 = `nlmnpekipjc × g`，自由出线 ×0.5（dgmaokfcpke.cs:270-280），过载系数 1.5
   - 渔轮 = 摩擦泄力上限 `poadfcckmhj()`（含过热降额），过载系数 1.75
   - 钩 = `nlmnpekipjc × g`（jbipdjaplgk.cs:169-177）
4. F ≤ limit → 安全；F > limit → 过载率 = clamp01((F−limit)/(limit×factor−limit))
5. **概率断裂**：每判定窗口以过载率 ×4/秒的随机尝试断线（FishingSet.cs:6016-6072）——瞬时越限+概率累积混合模型，不是纯磨损条
6. 断件 = 上限被突破者中最小者 → 上报 17/9 → 本地弹提示条 kNotification_LineBroken + 断线音效

## 七、根因排序与修复方向

**根因 1【主嫌】：f21 曲线池数值偏离官方真值** —— 同时解释两个症状：
- "没冲力/不挣扎感"：官方鱼外冲拉力仅为线强度的 10~30%（302 主条目 3.7~10.5kg @ 7828g）、搏鱼 5~15 分钟靠**持久的中等张力回合**；模拟器池要么不动（无对抗）、要么猛冲（g_carp 302 上限 46~58.7kg 接近/超过线强度）
- "g_carp 频繁断线"：g_carp 池条目外冲分布整体超线强度一档（对照 c.carp 主条目 8.7~30.4kg 安全线内）
- 修复：**官方 13 条真值注入 + 拉力按鱼重比例缩放**（fight_curves_fixture tunable 机制现成，先 A/B 实验）；同时校准 f5 体力池 per-gram（2.45~3.14）与 f6（逐鱼值，非恒 0.5628）

**根因 2：补发鱼节奏与客户端钓组状态机脱节**（f0=3 拒收）
- 修复：发鱼前核对 14/7 入水信号 + 无未清鱼 + 钓组处于等待态

**根因 3（低优先）：搏鱼期 4/22 形状**（零件裸树 vs 官方全树+运行位 1024）
- 不影响鱼运动，影响装备状态一致性；顺带修 11-11 的 args[7] 拒发 bug
