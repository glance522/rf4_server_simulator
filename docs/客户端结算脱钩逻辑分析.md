## 一、总图：脱钩的判定方是客户端，服务器纯被动确认【实证】

```
客户端搏鱼态 gfgapohfogm（状态2）每帧检查三条退场路径
  ① kldglnchdec   松口计时器到点           → f0=1 (eoemfihehog)
  ② kejihbadeej   钩保持 hazard 抽签命中   → f0=2 (ndfblamhelg)
  ③ dnblinaache   机动池单帧权重全零       → f0=2
  （外加鱼群系统异常 SchoolController → f0=2）
→ 任一命中 → hnpplmpbang(原因) → 状态机切 4（收尾）
→ 进状态4 hnffdebalii 时统一发 14/12（7 字段载荷，含原因+hooked+两个保持值遥测）
→ 服务器 hFishingLeft 收 14/12：
    f0=1/2/8 同分支：清鱼 → 结搏鱼磨损账 → (hooked=true 时)记 escapes+跑鱼播报
    → 保留钓组 → 重排咬钩发新鱼
```

关键点：
- 服务器**没有自己的脱钩判定**，与断线（17/9）一样是"客户端判定、服务器确认"。
- `f0=1`、`f0=2`、`f0=8` 在模拟器走**完全相同的分支**（handlers_game.go:1494-1535）；官方口径亦然——真脱钩与否只看服务器自己的 `st.Hooked`（14/11 中鱼确认时置位）。
- 14/12 载荷里 f1=`fejcgbcmobo`（张力保持值）、f2=`ponnlkamlao`（钩保持值）是客户端遥测，**模拟器只读 f0，f1/f2 全仓库无消费**（handlers_game.go:1420-1424）。

## 二、客户端三条退场路径详解

### 路径①：f0=1 松口计时器（kldglnchdec）——**进场时一次性掷骰，不是持续张力监测**

构造于搏鱼态入口（gfgapohfogm.geoplfemoon → kldglnchdec ctor，kldglnchdec.cs:54-113）：

**分支 1：底钓/静置类玩法（`effjdeblglh.bpoeccgmcfk()==false`【推断：浮漂类标志，false=底钓】）**
1. `pmfcjddcilk = 鱼当前对抗力 jfhcjbbkalp()`（nmhcohgdjon，定义体未恢复）
2. 多钩组缩放：`× (钩点数 kcgjlnmdbol / 钩数 pjkhmifjcng)`（int 整除，通常=1）
3. **玩家不活跃则 ×0.05**（kldglnchdec.cs:75-94）：
   - `!hkpcgmchofj() && !eeajjmkbjbi()` → ×0.05【推断：hkpcgmchofj=静置类玩法标志，eeajjmkbjbi=持竿活跃】
   - `hkpcgmchofj() && idmgpbkhbng() && !eeajjmkbjbi()` → ×0.05
4. **伯努利掷骰** `lphjocjojcp.mkkielhmcgn(pmfcjddcilk)`（即 `p ≥ Random.value`）：
   - 未通过 → 武装 `fhfpilhhhgo = Random(0.5, 2.0)` 秒计时器
   - 计时到点 → `fcalbphgmjk=true` → **f0=1**（gfgapohfogm.cs:236-239）

**分支 2：浮漂类玩法且鱼侧预置松弛参数（`aijdkdfbopd==true`）**
- `aijdkdfbopd/jjgmggmcebe/jecahdffgoc` 不是 tid27 字段，由鱼 AI 在咬前写入（eabkpandbch.cs:914-928）：
  当水场景==3 且概率 `mkkielhmcgn(归一化体力×0.4+0.4)` 通过时写 `jjgmggmcebe = 拉力×曲线×clamp((张力−0.05)×4)`、`jecahdffgoc = Random(0.3, 1.2)`；
  **概率不通过则立即脱钩**（eabkpandbch.cs:939-951）。
- 命中后走 `pmfcjddcilk = jjgmggmcebe`、计时 `Random(0.3, 1.2)` 秒 → f0=1。

> **对上一份断线文档 f0 表的修正**：f0=1 的成因是"搏鱼开始时的一次性保持力掷骰失败 + 延迟计时"，
> 不是"线松弛/张力归零监测到点"。持续张力响应在路径②的 hazard 速率里（见下）。
> 撒手不管（玩家不活跃）时 p ≈ 0.05×对抗值 → 几乎必跑，0.5~2 秒内报 f0=1。

### 路径②：f0=2 钩保持 hazard（kejihbadeej）——泊松抽签模型【实证】

载体 `ihlkhcenhfc` = SmoothDamp 平滑器：`nemmcmfbbef`=目标速率、`koomajjcigp`=当前平滑速率
（升 2 秒 / 降 0.2 秒，无速率上限，kejihbadeej.cs:293-296 + ihlkhcenhfc.cs:129-179）。
每帧：`fcalbphgmjk = mkkielhmcgn(koomajjcigp, 1.0, dt)` → **P(本帧脱钩) ≈ 速率×dt**（lphjocjojcp.cs:338-375，期望逃鱼时间 ≈ 1/速率）。

**基础速率 `c = coffdfkgfaa = 1 − clamp01(tid27.f20 × 场景系数)`**（kejihbadeej.cs:313-339）：
- f20（`adiddjkcdan`，tid27 静态参数块最后一个 float）= **钩保持强度系数**，是 kejihbadeej 唯一的 tid27 输入；
- 场景系数：玩家持竿活跃 → ×1；不活跃 → **×0.05**（→ c≈0.95，秒脱）。

**速率调制（kejihbadeej.cs:99-286）**：

| 调制项 | 条件 | 效果 | 证据 |
|---|---|---|---|
| 线松弛侧 | 受力 h < 阈值（`bihlodbgigm = clamp(鱼拉力×0.025, ≤0.25)×g`，g=9.81） | `× clamp01((1−√(h/thr))×35)`：h 低于 0.94×阈值时饱和=1（全额速率），h→阈值时→0 | kejihbadeej.cs:151-169 |
| 张力足够侧 | h ≥ 阈值 | `× (0.25 + 0.75×钩保持质量 pjonppibhbl)`（0.25~1 档） | :170-174 |
| 长搏降额 | 持竿且累计 >60s | 60→360s smoothstep 把 c 降到 c×0.0125（÷80）；>3600s→0（仅张力足够侧） | :117-149 |
| 机动张力系数 pfdkplenmif | 当前机动 | 默认1；300→0.7；306/308→0.1；307→0.4；**309 跃头→钩匹配度×9+1（最高×10，跃头期脱钩率暴涨）** | paldjjcggdd.cs:936-940 等各机动类 |
| 钩持质量 mckpinnohmg | 鱼（nmhcohgdjon）上的 0~1 因子【未闭环：锋利度/质量/磨损无法确认】 | `× clamp(值, 0.3, 1)` | :176-178 |
| 渔具类型常量 | **仅"从未主动搏鱼"期间生效** | 架型枚举∈{12-17,24-29,32,34}→×1/150；{18-23,30,31,33}或未知→×1/30 | :48-97, :181-252 |
| 终段门 | — | 不持竿 ×1.2；`mggbpmablco()`→0；`meaopokeiod()<0.01`→0 | :253-268 |

**定性公式**：
```
P(本帧脱钩) ≈ SmoothDamp→R (τup=2s, τdown=0.2s) × dt
R ≈ clamp(钩持质量,0.3,1) × pfdkplenmif(机动) × 渔具常量(仅未搏鱼) × 终段门
    × [ h<阈值 : (1−√(h/thr))×35 饱和 × c × (持竿?1:1.3)
      ; h≥阈值 : 长搏降额(c) × (0.25+0.75×pjonppibhbl) ]
c = 1 − clamp01(f20 × (持竿?1:0.05))
```

数值感受：模拟器发 f20≈0.9978 → 持竿活跃时 c≈0.0021/s → 基础期望 ~470s 才掷中一次，
长搏 6 分钟后再 ÷80 → **正常操作下 f0=2 几乎不可能发生**；撒手/掉竿 → c≈0.95 → 1~2 秒脱钩。

**刺鱼（14/9）与脱钩无关**【实证】：全库无任何刺鱼代码向 kldglnchdec/kejihbadeej 写入；
14/9 是纯遥测（FishingSet.cs:3585-3679 杆尖角速度超阈值计数上报）。刺鱼时机/力度不影响钩保持。

### 路径③：f0=2 引擎退出（dnblinaache）——机动池单帧权重全零【实证】

`dnblinaache.Update` 返回 false 的**唯一**现实来源：`llkfcijmgfd.iolmanmnenc` 选不出机动（返回 null），
而 null 只发生在"当帧池内所有条目 `动态权重 beiifmgdehc × 配置权重 aiobpbocjjg ≤ 0`"
（llkfcijmgfd.cs:764-943；池空不可能——兜底 301/307/308 的 hlbkfjnodei=0 永不移除）。

各机动动态权重归零门槛：

| 机动 id | 权重归零条件 | 证据 |
|---|---|---|
| 300 | 张力 ≤ 0.8 | hbiipolahad.cs:13-33 |
| 301/304/305 | 张力 ≤ 0.5 | hkhhbgfhlji.cs:227-246 |
| 302 | 张力 ≤ 0.5 或 钓组位移=0 | nkbcnogiiel.cs:62-83 |
| 306 | 张力 ≤ 0.25 或 鱼力≤0.05 或 钓组位移=0 | mlpeddobkhb.cs:113-135 |
| 307/308 | 钩匹配度 mfgmldbfaad ≤ 0.25 | mogeamcakfl.cs:10-31 / fghcdeoegog.cs:51-70 |
| 309 | 张力 ≤ 0.995 | acigmkabpao.cs:148-189 |

**解开了上一份文档 5.3 的"f0=2 引擎 14s 退出"待查项**：不是 c.carp 池 f16 耗尽（兜底永不耗尽），
最可能是某一帧**张力被拖低 + 钩匹配度低**同时满足，全池权重同帧归零 → 单帧雪崩 → f0=2。
（307/308 要求钩匹配度>0.25，小钩对大鱼 mfgmldbfaad 低时这两条兜底也是死的，全池归零门槛实际更低。）

另一 f0=2 来源（罕见）：鱼群系统 `SchoolController.dmcnmjdgicp().bdbebcnbbml()==false`（gfgapohfogm.cs:247-253）。

### f0=1 也会出现在状态 1（等待咬钩期）【实证】

状态1 `pmlepacfcfm.bachphcpjff`（pmlepacfcfm.cs:28-51）：鱼 AI 靠近/触碰饵后放弃时
鱼侧 `pbmoahdgkcm` 会被写 **1**（eabkpandbch.cs:949,965 / jpkkkbiacja.cs:143）或 **8**（从未咬兴趣离开）。

服务器对两者处理相同（见第四节）。

## 四、服务端（模拟器）现有处理【实证】

处理入口 `hFishingLeft`（internal/gameserver/handlers_game.go:1410-1559，注册 :1652）：

| f0 | 分支行为 |
|---|---|
| 1/2/8（脱钩/松口/未咬离场） | 清当前鱼（Pending=nil/Hooked=false/Resolved=false，**钓组保留在钓**，CastActive/InWater 不动）→ `settleFightReelWearState(...,"14/12")` 结搏鱼受力磨损账 → 若 `st.Hooked==true`：escapes 计数 + `recordHuntEscape` 大鱼补偿（grade≥3 设补偿窗口偏向下次发同档）+ `notifyFishEscape("脱钩离开")` 播报 → `scheduleBiteState` 重排咬钩发**新鱼** |
| 1/2/8 + 蓝冠天命鱼 | `LuckProtected && LuckRepush<2`：忽略脱钩，2s 后重推**同一尾**（最多2次） |
| 6 | 只取消计时器防重发，不清鱼不清 Hooked |
| 3/5（拒收） | PendingRepush≤2 时 6s 后重推同一尾；超限放弃等重抛 |
| 其他（0/4） | 保守收杆：CastActive=false 等 |

要点：
- **无超时强制收鱼**：搏鱼期服务器纯被动等 14/4/14/12/17/9（只有咬钩/重推 timer）。
- **服务器主动放鱼只有一处正经路径**：嘬饵否决 `finishNibbleHook`（fish_hunt.go:557-581 咬饵质量掷骰 + `hookRetentionFails` 保持率掷骰——仅"超钩容量"的鱼 hold<1，正常鱼 r≤1 时 hold=1 永不随机脱钩）→ 14/15 鱼离场（handlers_game.go:1379-1408）。
- **脱钩不结算钩/饵磨损**：per-catch 磨损（钩/拟饵/浮漂等）只在 14/4 成功渔获走（progress_ops.go:113-120）；脱钩只结渔轮摩擦片/轮体/竿件/前导的受力账（reel_fight_wear.go:432-514），推 [reel, rod, leader] 裸部件 4/22。饵料在 14/11 已扣，脱钩不退不补扣。与官方是否一致未验证（官方脱钩是否耗饵/磨钩无抓包证据）。
- 脱钩后同一尾鱼不再发；新鱼由咬钩重排 roll（fish_hunt 权重含 escape 补偿）。
- 跑鱼播报：`escapeTemplateKind` 有官方 401.f0 模板映射（7=鱼脱钩/6=断线/30=子线断/5=断竿/4=轮损坏/10=牙齿咬断），当前默认走 kind3 蓝色自由文案+语气词池（tunable `fish_escape_taunt` 可关回官方模板）（fishing.go:2541-2607）。

与 17/9 断线的状态机差异：断线走"非 KeepFight"分支时 CastActive=false + **全量装备树重建**（4/22 多件）；
脱钩不动装备、竿继续钓，只推 3 件磨损裸树。

## 六、对模拟器的启示（未动手改，仅结论）

1. **架构合规**：脱钩判定在客户端、服务器被动确认——模拟器现有 14/12 处理结构与官方一致，无需改判定。
2. **f0=2 14s 退出**（上份文档 5.3）已定位机制：客户端机动池单帧权重全零（张力+钩匹配度双低），
   属客户端本地物理表现，调 f21 曲线池（外冲分布）即可间接改善，服务器无 bug。
3. **想让脱钩"发生"得更真实**，服务端可调的只有 tid27：f20（钩保持系数）恒 0.9978 会让活跃搏鱼几乎零脱钩；
   官方真值未知，若要复现"小钩大鱼易脱钩"，需把 f20 与钩匹配度关联——但客户端 hazard 公式里钩尺寸的惩罚
   主要走 309 机动系数与 307/308 权重门（客户端本地），f20 是鱼种常量，**不要**把钩参数塞进 f20。
4. **f1/f2 遥测未消费**：可在 tunable 观测器（如 fight_load_probe 模式）里加 optional 记录，用于日后校准，
   不影响功能。
5. **可验证项**（下次实测）：撒手 5 秒看是否必来 f0=1/2（玩家不活跃 ×0.05 系数）；
   跃头机动（309）期间脱钩率应显著升高（×mfgmldbfaad×9+1）。

### 8.4 结论与归因排序（2026-11-12 二次修订：用户实测推翻"注意力"归因）

**用户实测反馈：手持路亚竿做动作（收线/抽停）时上鱼同样立刻秒脱钩**——排除"注意力在别的竿"。

#### 8.4.1 本轮源码新增硬证据【实证】

1. `hkpcgmchofj()` = `kcfbnmeplil` getter → **`gcnpahkoihk`（本钓组当前挂着鱼）**

2. `idmgpbkhbng()` 全库仅 kejihbadeej.cs:328 / kldglnchdec.cs:85 两处调用【定义体剥离】。

#### 8.5.4 与脱钩机制的闭环链【推断】

  判定翻车 → 保持力 ×0.05 → f0=1（0.5~2s）/f0=2（~1s）秒脱。
- 底钓竿架类不依赖这些组件的搏鱼挂载态（走无条件全值分支）→ 底钓零脱钩。
