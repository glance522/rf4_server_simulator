# 鱼口配置叠加/覆盖关系分析（2026-11-10）

## 范围与方法

管理后台能控制"鱼口"的配置分散在四个页面（钓场与鱼口、钩子手感、鱼饵偏好、游戏参数）。
本文逐一回答两个问题：

1. 每项配置参与判鱼管线的哪一步、带来什么影响（公式/取值）；
2. 配置之间是覆盖、叠加还是压制，后台 UI 是否把这些关系表达出来了。

依据：服务端代码逐段核对（行号见各表）；客户端源码 `E:\RF4\cs`（IL2CPP dump）核查鱼口职责边界。
所有合成公式均由本仓库当前代码直接读出，不是文档转述。

**一句话结论**：鱼口配置之间既有覆盖也有叠加，存在几个后台 UI 没有表达出来的"静默失效"坑；
客户端在鱼口上完全被动，不存在双份配置叠加；后台值得改的是信息展示与防呆，不是合成逻辑本身。

## 1. 判鱼管线总览

> **2026-11-14 更新**：④ 选鱼权重链的 C1 之后新增两个环节——**G 硬性鱼口门**
> （`bite_gate_enabled`，默认关：拟饵×食性硬剔 / 水层 ±0.15 超界 ×0.01 地板 /
> 天然饵攻略+生态双票）与**区域固定鱼种名册**（`fish_zone` 表，独占/增益两模式，
> 后台钓场页可编辑）；剔空候选经 `gateBlocked` 压制内置鱼池兜底。
> 「鱼汛模式」卡片二选一（遗留/真实鱼汛）原子统管五个开关。详见
> `specs/changes/bite-gates-and-zones/spec.md` 与 `docs/gameplay.md`。

一杆从抛竿入水到 14/14 推鱼，配置按以下顺序生效：

```
① 排定时器 scheduleBiteState (fishing.go:1780)
     delay = 延迟链(阶段A) × 钩型自动因子
② 到点守门 onRodBiteTimerTicket (fishing.go:1865)
     落水保护 / Motionless 12s 兜底 → 顺延，不改概率
③ 概率掷骰 (fishing.go:1968-1979)
     p = bite_probability(水域覆盖替换) → [0.95 上限] → × 窝料死窝闸门 → rand
     失败 → emptyWeatherBiteLocked 同链重排下一轮
④ 选鱼权重链 rollFishFromDBWithRules (fishing.go:764-965)
     静态名册 → 水域覆盖(替换) → 饵料规则(剔除+score) × 分布 × 生态 × 钓点 × 窝料 × 饵效证据
     → weightedChoice → 欢乐时光二次掷骰门禁
⑤ 重量/档位采样 (fishing.go:1018-1200, fish_hunt.go)
     grade_ratio(总闸) / 鱼猎四阶段 / 钩型软匹配 / 重量上限
⑥ 中钩确认 (fish_hunt.go:536-560, 14/11 时)
     嘬饵判定 / 保持率抽样 —— 与③④的概率、档位完全独立
```

## 3. 阶段 A：咬钩延迟（鱼多久来咬）

**最终公式**（`fishing.go:1842-1844`）：

```
延迟 = [fixed 直通 或 (样本×天气×技能 → 保底6s → cap上限 → ×倍率)] × 钩型自动因子
```

| # | 配置项 | 位置/默认 | 具体影响 | 与其他配置的关系 |
|---|---|---|---|---|
| A1 | `bite_delay_fixed` | 游戏参数页+水域编辑器；全局 0 | `>0` 时**整条链短路**：直接返回 `max(0.05, fixed)`（fishing.go:409-411）。天气因子、技能、倍率、上限全部无效；落水保护也改用 fixed（fishing.go:428-431） | 最高优先级，覆盖 A3~A6；唯一压不住 A7 钩型因子——fixed=10 实际出 9.0~12.0s |
| A2 | 官服延迟样本池 | 代码内置，不可配 | 32 个真实抓包样本（≥6s，fishing.go:317-333）随机抽一个作底 | A1 关闭时才参与 |
| A3 | `fish_weather_enabled` | 鱼群规则条；关 | 开启后乘 `weatherDelay = 1/√(active/total)`：按名册逐鱼算天气活跃度（季节×天气型×水温高斯×浑浊度×活动强度，单鱼 clamp [0.15,1.25]，fishing_weather_fishing.go:9-22）加权平均；因子范围 ≈ 0.89~2.58 | 乘法叠加在 A2 之后；间接依赖 `fish_weight_override`（禁用鱼从延迟名册剔除，fishing_weather_fishing.go:41-49）和饵料过滤（:65-71）——改鱼种列表会改变延迟节奏；关闭恒为 1 |
| A4 | 技能 BiteSpeed | 玩家技能，不可配 | `1 − 熟练度×0.15/10×0.03`，下限 0.5（skills_ops.go:339-343）；满练度 ≈0.95 | 乘法，在 A3 之后 |
| A5 | `bite_delay_max` / `bite_delay_lure_max` | 默认 20 / 6 | 上限截断：普通竿先保底 6s 再 cap；路亚保底 0.8s 再 cap；`bite_delay_max<6` 时落水保护缩到该值（fishing.go:435-439） | **cap 在倍率之前**——A6 可突破上限 |
| A6 | `bite_delay_scale` | 默认 1.0 | cap 之后整体乘（fishing.go:462-464），0.5=快一倍；落水保护 = max(6s 或 A5)×scale，下限 0.8s（fishing.go:440-448） | 被 A1 短路；乘在 cap 之后 |
| A7 | 钩型自动因子 | 不可配（item_def） | `0.90+0.30×hookScore` ∈ [0.90,1.20]；hookScore = 0.65×(钩号/33)+0.35×((钩长mm−1.8)/(76−1.8)) 各 clamp（fish_hunt.go:402-425）；大钩慢小钩快 | 整条链**最外层**（fishing.go:1843），不受 cap/scale 约束，连 A1 fixed 也压不住。钩子手感页"咬口倍率"不参与这里 |
| A8 | 水域覆盖组 `fish_bite_setting` | 水域编辑器"调整" | A1/A5/A6+B1 五项**整组替换**全局 tunables（fishing.go:391-398）；保存永远五列全量写（repos_admin_panel.go:650-663），逐列部分覆盖只有直写数据库才可达 | 覆盖全局；「恢复默认鱼口」删行回全局 |

## 4. 阶段 B：本轮咬不咬（概率掷骰，fishing.go:1968-1979）

**公式**：`rand < min?(bite_probability, 0.95) × 窝料闸门` → 失败走空轮重排。

| # | 配置项 | 位置/默认 | 具体影响 | 与其他配置的关系 |
|---|---|---|---|---|
| B1 | `bite_probability` | 默认 1.0 | 每轮判鱼基础命中概率，clamp [0,1]；1=每轮必出 | 水域覆盖整组替换全局（fishing.go:484-486）；被 B2 条件封顶、B3 相乘 |
| B2 | 0.95 上限 | 隐式规则，无 UI | `fish_bait_rules_enabled==1 或 fish_weather_enabled==1` 时 `p=min(p,0.95)`（fishing.go:1969-1971）；**两开关全关时无上限** | 上限条件由 C2/C3 开关决定——开它们会让"必出"变"95%" |
| B3 | `groundbait_enabled` + `groundbait_overdose_from`(15)/`step`(0.15)/`lure_exempt`(1) | **无 UI** | 死窝闸门：净窝份数 >15 起 `P=1−0.15×(份数−15)`，≥22 份 P=0 该格不开口；路亚族默认豁免（groundbait.go:601-609, 893-914） | 乘法闸门压 B1 |
| B4 | 空轮重排 `emptyWeatherBiteLocked` | 行为 | 掷骰失败或选不出鱼 → 置 Resolved 后用阶段 A 同一条延迟链重排（fishing_weather_fishing.go:92-105） | "天气鱼口的间歇试口"= 低概率×多次重试，非独立概率通道；实际开口频率 ≈ 概率 ÷ 平均延迟 |
| — | `arm_next_fish` GM 指令 | 管理命令 | 绕过 B 全部掷骰与两道重量上限（fishing.go:1931-1955） | 最高优先 |

## 5. 阶段 C：出什么鱼（权重链，fishing.go:764-965）

执行顺序即下表顺序，每步都是上一步结果继续往下乘/被替换：

| # | 配置项 | 位置/默认 | 具体影响 | 与其他配置的关系 |
|---|---|---|---|---|
| C0 | 静态名册 | 只读静态库 `loc_wiki_fish`+`loc_fish.catches` | 底权（缺统计保底 1） | 被以下所有层加工 |
| C1 | 水域鱼种覆盖 `fish_weight_override` | 水域编辑器 | 命中鱼种 → **替换**静态权重；`enabled=false` 或 weight≤0 → 权重 0 硬过滤；名册外鱼种可追加（fishing.go:790-818）。⚠ **全部为 0 且 C2/C4/C5 三开关全关时，整组覆盖被静默忽略、回退静态名册照常出鱼**（fishing.go:813-817） | 替换 C0；同一组覆盖还被 A3 延迟名册引用 |
| C2 | `fish_bait_rules_enabled` | 鱼群规则条；关 | 开启=strict 通道：deny 命中/底钓只吃不符/前置条件（海图区号、jig 阶梯、上船等）不满足 → **整鱼剔除**；保留鱼乘 score：允许或有证据 `1+0.5×variation`、同食性合法替代 ×0.086、多饵同时允许 ×1.15（fishing_bait_rules.go:315-380）；同时算 interest（min(1, 滤后/原权重/1.725)）供欢乐时光掷骰 | 参与 B2 的 0.95 条件；C3 覆盖规则依赖本开关 |
| C3 | `fish_bait_override`（吃/不吃/底钓只吃/前置条件/轮换组/间隔/模式） | 鱼饵偏好页 | 存在且 enabled=1 → **整行替换**内置 252 条规则；enabled=0 回落内置（repos_fish_bait_override.go:56-83）。轮换：当前组饵 ×3、组外 ×0.5（soft）；**strict 模式组外饵整轮不咬**（fishing_bait_override.go:156-172） | 依赖 C2 开启；替换内置规则 |
| C4 | `fish_distribution_enabled` | 鱼群规则条；关 | 乘 `(0.15+3.85v²)×昼夜系数`：v 为按"区域(40×40 格)/鱼种/4 游戏小时"的确定性哈希，**v<0.3 → 权重 0**；夜行鱼夜 ×1.8/昼 ×0.35（fish_distribution.go:35-51） | 乘法门禁；同区同鱼全服一致，不因换饵重抽 |
| C5 | `fish_ecology_enabled`（**无 UI**） | api 可设；关 | 开启后乘 ~14 因子各 `clamp(值,floor,2)^0.35`（首因子水层 floor 0.05、指数 0.60）：水层/昼夜/季节/天气型/天气附加/水温/浑浊度/光照/钓点底质水流/拟饵动作/运动状态/稀有度(1+RareFish×RarityTier×0.12)/拟饵本体/技能环境；技能 tolerance 把 <1 因子往 1 拉回最多 45%；整体 clamp [0.08,2.5]（fish_ecology.go:283-348）；`fish_ecology` 表单鱼 enabled=0 → 该鱼权重 0 | 乘法叠加；**不做饵料放行**（禁饵在 C2 已删）；依赖技能节点与天气计划作输入 |
| C6 | 钓点偏移 spotPref | 内置不可配 | 乘法 | — |
| C7 | `groundbait_enabled` + `groundbait_gain`(1.5)/`cap`(2.60)/`sat`(4)/`special_gain`(0.3)/`soft_max`(0.6)/`soft_beta`(0.45)/`special_margin`(0.08)/距离三参(4/7/10m)（**全部无 UI**） | tunables | 窝料乘子 `M=1+(min(2.60, 1+1.5×S×a×(1+0.3×spec)×√(硬门×软门))−1)×P`，仅 M>1 生效（groundbait.go:706-708, 870-889）；S=1−exp(−份数/4)；硬门=水层×昼夜×季节×稀有度×底质×流速 clamp[0.05,1]；软门=水温×低温×水色被对口窝料按 β 软化；掠食鱼冻结恒 ×1 | 乘法叠加在 C5 之后；同份数同时进 B3 闸门——窝越多对口鱼越强但开口率越低 |
| C8 | `bait_pref_scale` | 游戏参数页；1 | 非 strict 通道的饵效证据层：tier3 ×8 / tier2 ×4 / 在列 ×2，再 ×`bait_pref_scale`；未上榜 ×(0.9−0.6×覆盖度)×scale（fishing.go:852-880）；**设 0 = 整层关闭**（含 C9） | 只在 C2 关闭时生效；与 C3 是两条独立通道 |
| C9 | `bait_pref_weight_shift` | 游戏参数页；1 | 不改权重，改**体重分布峰值**：mode=1+0.12×tier×shift（tier≥2 才生效，fishing.go:985-1010）——tier3 饵峰值 ×1.36 招大鱼 | 被 C8=0 关闭；进入阶段 D 采样 |
| C10 | `happy_hour_enabled` + BiteBonus=0.1 | 鱼群规则条；开 | **不是权重乘子**，是选鱼定稿后的二次掷骰：`chance=interest×(1+0.1)×天气活跃度`，interest≤0.1 封顶 0.1，失败整轮作废重排（fishing.go:931、happy_hour.go:64-86） | 仅 `forRig`（C2∨天气∨欢乐时光>0）时启用；三个全关时此掷骰整体跳过必过；interest 来自 C2，天气活跃度来自 C5 因子 |

## 9. 客户端源码核查结论（E:\RF4\cs）

- **客户端在鱼口上完全被动**：14/14（载荷 27）是"有鱼咬"的唯一信号源，载荷不含任何时间/延迟字段；

## 11. 后台修改建议

**P1 信息一致性（小改动，解决"改了不生效"类困惑）**

1. 水域编辑器：`fish_bite_setting` 有覆盖行时显示"⚠ 此水域正在覆盖全局参数"徽标；
   游戏参数页五个延迟/概率 key 旁显示"已被 N 个水域覆盖"。
2. 游戏参数页 `bite_probability` 说明补"开启鱼饵偏好或天气鱼口后，上鱼概率上限为 0.95"。
3. 水域编辑器延迟参数区加生效顺序说明：水域覆盖 > 全局；固定延迟生效时倍率/上限无效；
   实际延迟还会乘钩型自动因子 ±10~20%。

**P2 语义防呆（中等）**

4. 鱼种列表全部为 0 且三个规则开关全关时，保存前弹确认"将回退到静态名册照常出鱼"（坑 2）。
5. 钩子手感页说明改为三段职责：本页只管"咬了能不能中、中了能不能保住"，不管咬钩快慢。
6. `fixed>0` 时前端把倍率/上限输入框置灰。

**P3 补齐入口（较大，可另开任务）**

7. 鱼群规则条或游戏参数页增加 `fish_ecology_enabled`、`fish_hunt_enabled`、`groundbait_enabled` 开关，与文档对齐。

以上均属后台/玩法功能改动，动手前按仓库纪律建 `specs/changes/<slug>/spec.md`。
