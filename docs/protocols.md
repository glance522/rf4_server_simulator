# 协议参考（已实现命令）

按字节布局逐条记录 `gameserver` 已注册的 realtime 命令与推送；已展开会话、物品、邮箱、市场、工坊、商店、钓组、钓鱼、社交等家族。

- **适用客户端**：`4.0.25034`
- **数据来源**：`command_contract.json`、`wire_spec.json`、`command_responses.json`、`csnames.go`
- **字节号**：结构内相对偏移，`a–b` 表示该类型连续覆盖的字节区间（等价于合并单元格）。
- **变长字段**用 `n` / `m` / `L` 表示，后续偏移顺延；嵌套结构单独成表并被引用。
- **类型**：`byte`、`ushort`、`uint`、`ulong`、`int`、`char[]`、`Guid`、`object`。
- **备注**：编码细节，如 f32 位型、端序、变长、引用。
- **附注**：字段行为、约束、副作用；命令级说明放在表尾 `命令级` 行。
- **客户端字段名 / wire 类名**不放进主表，见「附录 A：字段对照」。

## 维护约定

| 项 | 约定 |
|---|---|
| 主表 | 人工维护，只写字节、类型、人类可读含义、编码细节和行为 |
| 附录 A | 客户端逆向 / 代码检索用；可按 `wire_spec.json` 重新生成 |
| 抓包解码 | 先读 T0 帧头 → 信封 → `type_id` → 对应命令表 / 附录 A |
| 版本变化 | 附录跟随 `wire_spec`；主表只改语义变化 |
| 长单元格 | 用 `<br>` 换行，避免单行过长 |

## 证据与置信度

每个命令章节标题下的 `> 证据：...` 行表示该协议的来源和置信度。

| 来源 | 含义 |
|---|---|
| `CON` | `command_contract.json` |
| `WIRE` | `wire_spec.json` 的 type/class |
| `CODE` | `gameserver` 实现 |
| `CAP` | 实机抓包 |
| `EMP` | 实测、日志、客户端行为证据 |
| `DEC` | 客户端反编译 |
| `DYNAMIC` | `map_defs` / `sonar_grids` / 运行时资源生成 |

| 置信度 | 含义 |
|---|---|
| `A` | 有抓包/实测/反编译证据，且与代码一致 |
| `B` | 契约 + 代码一致，未实机验证 |
| `C` | 无契约，或只有代码/类型表 |
| `D` | 空实现、固定占位或未实现 |

> 未在 `> 证据：` 行中列出的来源，表示当前没有该来源的直接证据。

## T0 通用头

绝对偏移，从帧首字节 0 开始；所有命令共用。

| 字节号 | 数据类型 | 字段描述 | 可选项及描述 | 备注 | 附注 |
|---|---|---|---|---|---|
| 0–3 | uint | `body_len` 帧体长度 | `0`=4 字节保活帧；`1`=仅 type 帧；`≥9`=正常帧 | 小端，`9 + payload` | — |
| 4 | byte | `frame_type` 帧类型 | `0`=数据；`1`=ACK | ACK 无 payload | — |
| 5–12 | ulong | `wire_id` 帧序号 | — | 小端，单调递增 | — |
| 13 | byte | 信封前缀 | 固定 `0x01` | — | — |
| 14–17 | int | `marker` 信封标记 | `-1`=请求/推送；`-2`=响应；`-3`=失败 | 小端 | — |
| 18–21 | uint | `call_id` 调用号 | — | 响应回显请求值 | — |
| 22 | byte | `main` 主命令 | — | 仅 `marker=-1` | — |
| 23 | byte | `sub` 子命令 | — | 仅 `marker=-1` | — |
| 24–n | byte[] | `body` 命令负载 | — | 见各命令表 | — |
| n+1 | byte | `expect` 是否要响应 | `0x00`=期望响应；`0x01`=免响应 | 仅 `marker=-1` | — |

> `marker=-2` / `-3` 没有 `main` / `sub`，`body` 从字节 22 开始。
> `marker=-3` 的 body 为 `u32 len + error_type + u32 len + message`，不走值编码。
