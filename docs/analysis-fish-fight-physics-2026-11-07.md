## 一、总架构：服务端"发牌+记账"，客户端"本地物理"

服务端在搏鱼期间**不模拟任何力学**——14/8（搏鱼遥测，含鱼疲劳/力量比/线载统计 25 个 float）只被 `hFishingLoad` 原样忽略（`handlers_game.go:1377`）。全部动力学在客户端本地跑，服务端的职责是**在 14/14 那一刻把整包参数算好发下去**，之后只等 14/12（跑鱼/脱钩）或 14/4（收竿）记账。这个定位与客户端 dump 完全互相印证。

时序：14/2 抛竿 → `scheduleBite` 按官方延迟分布排 timer（中位 13s，`fishing.go:288-346`）→ 判鱼 `rollFishForRig`（`fishing.go:569`）→ `Push14_14`（`fishing.go:1426`）→ 客户端建鱼实体回 14/12 f0=6 → 14/11 刺鱼确认 → 搏鱼（客户端本地）→ 14/12（挣脱/脱钩）或 14/4（收竿结算）。

## 三、鱼的运动轨迹（客户端 Fish AI）

- **状态机**：刺中初始段用 100 系曲线行，主搏段用 300 系（客户端只收 {300,301,302,304,305,306,309}；官方抓包同样不发 307/308 等，走客户端内置兜底，行为一致）。
- **阶段选择**：只考虑阶段序号（f15）最高的非零权重组；组内按 `f1 权重 × 机动动态权重`（由鱼实时状态计算）加权随机；f16=行使用次数上限。
- **方向**：360° 绕圈扫描（9°~17° 步进）→ 目标夹角加权（`dot²×1000+1`）→ 射线验水路 → 按权随机；300 系连续机动继承目标点 → 连续弧段。
- **俯仰/水层**：由"距底/距水面余量"反馈控制（±105° 约束角），把鱼锁在水层内；贴底减速、跳跃（306/310-312 + 疲惫态概率起跳）。
- **机动类型**：100 待机 / 101 强制左转 / 102 强制右转 / 103 直行停顿 / 104 通用转向 / 105 复合主搏段 / 200 贴底朝玩家 / 301 冲向玩家 / 302 下潜拉力渐衰 / 304 横向急游 / 305 翻滚 / 306 水面翻腾 / 307 暴冲甩头 / 309 贴身最后挣扎 / 310-312 跃出抛物线 / 400 远逃 / 500 瘫软。
- **速度**：期望速度 ← 行 f4/f5 幅度列采样派生；极速和转向敏捷都乘**体力衰减 LUT**——鱼越累游得越慢、转得越钝。
- **上岸判定与体力无关**：水平距 ≤1.25m + 收线进度 >0.85 + x 窗口（浮漂类另有高度/0.801×范围条件）。

详见报告 1/4。

## 四、动作拉力（客户端力学链）

```
曲线行 f8/f9（拉力下/上限，单位牛）
  → 每次机动 Random.Range(lo,hi) × 鱼力量比(0.1..1)   ← 动作拉力
  → 写 param12 → BodyMotor 施力于鱼刚体
线 = ConfigurableJoint 弹簧链，张力 = 刚度×伸长×0.102×g（胡克定律）
线载每帧 = SmoothDamp( min(线弹簧张力汇总, 需求负载) )，牛
上限链 = min(竿×弯角系数[1..2.5], 线×0.5(搏鱼), 前导, 轮)，全部 kg×9.81 化牛
超载：仅当归一化线载>0.5 时查最弱件；每帧断件概率 ≈ 4×超载比率
     （倍率：线1.5 / 轮1.75 / 竿3.5）→ 17/9 上报 → 服务端 resolveGearBreak 重裁决
```

- 曲线行拉力列单位是**牛**（客户端本地兜底行 400 组 = 体重kg×10..30×g 构造）。
- **obj27.f8 在客户端没有"直接乘进力"的路径**——它只用于曲线重建比较和 14/8 echo；真正的力来自曲线行列。服务端把 f8 当"曲线标定基准"用（`scale = pull/baseTension`）恰好是对的。
- 存疑项：泄力公式 `Reel.cs:106` 的 `(1−x)·0.05+0.95` 形态与预期 `0.05+0.95x` 相反，需 IDA 复核字节码；线杯打滑放线方法体未定位。

详见报告 2/4。

## 五、鱼的耐力（客户端唯一积分器，无恢复）

```csharp
// nmhcohgdjon.cs:687-720 dpjclmgalfb —— 全工程唯一写入点
疲劳 += (1 − f6) × 5 × 挣扎功率 × dt
挣扎功率 = clamp(1 − 实际速度/期望速度, 0.25, 1) × 期望速度 × 极速，封顶 3×线力（线不绷紧 ÷10）
力量比 = clamp(1 − (疲劳/容量)², 0.1, 1)，容量 = rand(0.7..1) × f5
```

- **扣体力的不是"冲刺事件"而是"受阻程度"**：被线拉住想跑跑不动时扣最多；"休息"机动只是让消耗趋近 0，**不回血**——本 dump 无任何恢复路径。
- **f6 语义修正（重要）**：f6 是**抗疲劳系数**，不是"开局体力比"。f6=1 ⇒ 永不疲劳（正是测试鱼 f6=1 + 池 1e7 的无限体力实现）。官方 f6 逐鱼在 [0.01, 0.8] 变化；服务端现用单样本常数 0.5628（疲劳速率 ×0.437）。
- 力量比三处反馈成"越拉越温顺"：趴底概率 ∝ `(1−力量比)×0.2+1`、起跑概率 ∝ `力量比×0.4+0.4`、中途放弃 ∝ `(1−力量比)×0.15`；动作拉力采样也乘力量比 → 越拉越轻。
- **没有"力竭判负"**：力量比钳底 0.1，客户端不把体力归零当收鱼条件；失败出口只有挣脱/脱钩——f20 基数 + 搏鱼 60 秒后安全余量经 300 秒 smoothstep 衰减到 1.25% + 线松弛时脱钩速率放大至多 35 倍 + 钓组系数（1/150 或 1/30）。
- HUD **没有**鱼体力条；鱼疲劳/力量比通过 14/8 上行对服务端可见（服务端忽略）。

详见报告 3/4。

## 六、人物耐力

- **308.f0 服务端权威**（0..1），客户端只有 10 秒 SmoothDamp 显示，**无本地消耗/恢复公式，也不上报**——官方实测 67 分钟会话仅 [0.830, 0.85] 缓降。
- 服务端现状：**恒 0.85**（`repos_player_condition.go:9`，`UpsertPlayerCondition` 无任何业务调用）——人物耐力实际上是无穷。收线速度、摇轮、顶竿在客户端都不读这个值（全库零交叉引用），竿弯量只影响装备侧载上限。
- 将来要实现时的现成通道：低能量拒绝 = 操作错误码 84（`kOperationResult_LowEnergyLevel`）；消耗输入可用 14/8.f23/f24（收线过程量/累计做功）+ 14/9 拉拽 + 3/9 活动位；推送节奏 ~15s，10 秒平滑交给客户端。

详见报告 4/4。
