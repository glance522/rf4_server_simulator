## 一、结论先行

**鱼的作用力确实有两处系统性问题，均已 A 级证据定量证实：**

1. **27.f8 拉力（曲线缩放基准）全线偏低 14%–49%**（21 样本无一例外，均值 ≈ −28%）。
   官方 f8 = 体重(kg) × **逐鱼种 k**（12.6–20.6 N/kg，种内稳定 ±3%）；
   模拟器用常数 0.00980665 N/g（= 1 kgf/kg）× archetype 猜测系数。
2. **27.f21 曲线多了一层官方不存在的逐阶段张力系数**（`fightPhaseTensionScale`）。
   决定性证据：官方每鱼曲线 = **鱼种池 × 单一 uniform scale 逐行精确成立**
   （perch 221g = 模拟器 perch 池 × 0.19375 逐行误差 <0.1%；crucian 293g = ×1.47233；
   c.roach 680g = ×4.6066），**没有任何逐阶段乘数**。该自造层把主搏段 105 压到
   官方的 22%、把下潜 302 抬到官方的 132%、翻腾 306 压到 31%、转向 104 压到 46%。

此外 f5（体力池）逐鱼种 rate 与模拟器 archetype 猜测有 −78%~+46% 的离散偏差
（海钓 merlang −78%、piksha −62% 最严重）；f6 官方是逐鱼种量化值（0.05 步进），
模拟器发常数 0.5628。

## 四、修正方案（按优先级，落地走 specs/changes/<slug>/spec.md）

### 为什么改这三层：力的传递链

搏鱼期间服务端不做实时力学（逆向已确认）：咬钩那一刻 14/14 发一次 27 对象参数包，
之后全是客户端本地模拟。所以"鱼的作用力对不对"取决于参数包里两样东西：
表的绝对量级（由 f8 的缩放决定）和表的阶段比例。

```
服务端（我们改的地方）                          客户端（不改，只吃结果）
池模板 = 每鱼种一张"动作→拉力(牛顿)"表
   │
   │  ×(f8 ÷ 模板基准)        ← P1a 修这里：f8 算小了 ~28%
   │  ×逐阶段系数(自造)        ← P1b 删这里：官方没有这一步
   ▼
27.f21 表 ──────────────────────────────→ 客户端直接按表里的牛顿数给鱼施力
27.f8   ──────────────────────────────→ 只做标定/回显，不参与乘法
27.f5/f6 ─────────────────────────────→ 决定鱼多快累、能挣扎多久（P3 修这里）
```

- **P1 = 修"大小"和"比例"，不动表本身**：P1a 换 f8 公式（整体 +28% 回官方量级）；
  P1b 删逐阶段乘数（主搏段 105 恢复 4.5 倍、翻腾 306 恢复 3 倍——现在"该狠的时候不狠"）。
- **P2 = 给 6 种鱼换官方真表**：现在 merlang 借 crucian 28 行池（官方 8 行）、
  piksha 借 perch 池等 6 处错配；今日抓包有这 6 种完整官方表，直接导出入库直配。
- **P3 = 修"力"以外、决定搏鱼节奏的字段**：f5 体力池（海钓官方值是我们发的
  2.6~4.5 倍，现在海钓鱼很快蔫）、f6 抗疲劳系数（官方 per-species 0.05 步进量化值，
  我们全鱼种发 0.5628）、f16/f20 小修。

### P1 作用力主链（本问直接命中，一处 spec）

1. **f8 逐鱼种 k 表**：`officialSpeciesStatics` 增加 k 列（上表 11 种 + fallback 17.0），
   `fishFightPullFor` 改 `pull = w_kg × k`（保留 `fight_power_scale` tunable 与可选
   `+0.35·ln(w)` 精修开关）；`verifiedForcePerGram` 降级为"未知鱼种旧口径"注释，
   不再作主路径。**profile.ForceScale 从 f8 路径移除**（官方 k 无 archetype 形状）。
2. **删 `fightPhaseTensionScale` / `fightPhaseDurationScale` 逐阶段乘数**：
   `buildFightCurvesWithProfile` 改纯 uniform：`scale = pull / poolRow100Tension`，
   张力与 duration 列都按池原值缩放，不再乘阶段系数。`profile.Duration/RestScale`
   一并停用（官方 duration 不随体重变）。
3. 测试迁移：`TestFish27UsesVerifiedFightFields` 的 B 级断言（53g/63g 严格
   0.00980665）改为 k 表口径 + A 级样本断言；`TestFightCurvesKeepSprintTensionStages`
   /`TestFishFightProfilesUseSpeciesAndWeight` 的张力断言按新口径重算。

### P2 官方鱼种池入库 + 直配

从今日抓包导出 taran/b_gill/n.pike/merlang/piksha/din_l_carp 六个池（含 f15/f16
等 int 列），fight_curves_sets.json 按鱼种键直配，去掉 archetype 池猜测映射的
6 处错配；crucian/perch/c.roach 已验证不动（c.roach 两行微差按官方修）。

### P3 逐鱼参数表

- f6 per-species 表（官方 0.05 步进值，11 种全有；`fishQuality()` 死代码复活或直表）。
- f5 per-species rate 表（海钓 merlang/piksha 优先，−78%/−62% 直接拉长搏鱼时长）。
- f16/f20 顺带按官方表填。

### 风险与回归

- 力整体 +28% 均值、302 −32%/105 +4.5 倍的相对变化是**可感知**的：改后必须实机
  A/B（同杆同鱼种溜鱼手感、泄力报警时机、断件频率）。
- 装备磨损/拉力尖峰统计走客户端线载，不受本改动影响；服务端结算侧
  `fishFightPullKgfFor` 跟随 f8 变化（泄力比较基准同步 +28%，需回归断线判定样本）。
- 与 F2（fixture 行异常）无交集：不建议启用 `fight_curves_fixture`。

### 6.4 实现口径（v1 = 习性表，v2 = 逐鱼种实测覆盖）

```
k(fish) = K0(习性组) + 0.35·ln(w_kg)     # 组基值来自 6.1/6.2 表
不确定度：组有锚点(≥2样本) ±0.5；纯估计组 ±1.5
无组归属 → 17.5
```

- v1 就能把未测种的 f8 偏差从现状 −30~−50% 压到 ±10% 以内（习性表）；已测 15 种
  精确到 ±3%。
- v2 = 按 6.3 清单补抓，锚点组逐个把 ±1.5 收敛到 ±0.5。组锚点钉死后组内其余种
  按体型插值（同一习性组内 k 与成鱼体型单调，误差 ±0.5）。
- 两条已证实的先验可写进表注释：同科体型梯度单调、海水/洄游加成 +1~+2。
