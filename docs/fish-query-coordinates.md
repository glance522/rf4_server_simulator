# 查鱼坐标换算

客户端兼容基线为 `4.0.25034`。HUD 坐标单位不随地图图片尺寸或界面缩放改变；纸地图能覆盖的坐标范围则由图片尺寸及其标定参数共同决定。

## 已核对的换算

- HUD 使用人物位置减去场景原点后的 X、Z，各除以 5，再按最近偶数规则取整。
- 地图鼠标悬停读数对应鼠标所在位置，不一定等于人物 HUD；核对人物坐标时应比较同一时刻的同一位置。
- 人物位置上报 `3/9` 使用同一个场景相对位置，但不除以 5。
- [事实] 当前客户端公共抛竿路径把钓组位置的 X/Z 直接传入 `14/2` 落点字段；已核对的底钓实现返回鱼钩世界位置，不减地形原点。依据为当前客户端的运行时类型、调用链与只读位置对照，不把人物位置日志当作鱼饵落点。其他钓组未逐项实机抛竿验证。
- 因而显示坐标差 1 对应 5 个世界单位。水平直线距离为 `5 × hypot(显示X差, 显示Z差)`；整数显示会损失精度，这不是线长、卡米数或可达抛距。
- 服务端鱼群区域仍按实际判鱼坐标的 `floor(X/40), floor(Z/40)` 划分。一个区域跨度对应 8×8 显示单位，但区域起点取决于判鱼坐标与场景原点的关系。

## 使用边界

转换函数必须传入与待转换坐标属于同一坐标系的、已经核对的场景原点；不能对所有地图默认原点为零。`14/2` 世界落点转换为显示坐标时减去地形原点，`3/9` 人物相对坐标则不能再减一次。

区域采用左闭右开范围 `[最小值, 最大值)`。例如原点为零时，世界 X `[400,440)` 对应连续显示坐标 `[80,88)`；HUD 接近边界时可能提前四舍五入显示为 88。转换范围不先取整，以免把相邻区域算进来。

显示坐标反算只能得到中心代表值，不能还原 HUD 取整前的精确位置。区域边界也不等于水岸、可行走范围或真实水域边界；全图扫描需要另有可靠的数值边界，不能从攻略点包围盒推定。

## 已启用的内陆区域查询

[事实] 区域查询使用十七个原点、地形范围和纸地图标定已核对的场景，包含十六个单 Terrain 场景和拉多加湖群岛。扫描范围取地形与纸地图的交集，不使用历史钓获点的包围盒。源码支持表为 `fishQueryRegionScenes`（单一事实源在 `internal/fishmaps`，gameserver 与管理后台地图编辑器共用），保存各图原点、地形边长及纸地图数值标定，不以缺省零原点适配未知地图。

[事实] 当前客户端纸地图的位置指针使用 `图片内位置 = 场景相对世界位置 × scale + offset`，鼠标悬停采用其逆换算，再除以 5 得到显示坐标。纸地图设置包含各自的偏移、缩放和贴图尺寸；显示控件按贴图尺寸建立局部范围，界面缩放不改变对应世界范围。依据为当前客户端离线资源中的具名数值字段及位置指针、悬停逆换算、显示控件初始化调用点，不依赖截图识别或图片内容。

因此，纸地图每轴覆盖的场景相对世界范围为 `[-offset / scale, (图片尺寸 - offset) / scale)`；加上原地形原点后，与 `TerrainData` 世界范围相交。标定保留客户端 `float32` 数值精度，区间计算使用 `float64`。不移动显示原点，也不把获胜区域的坐标事后挪回地图内：必须先裁剪扫描范围，再计算粗筛评分及配饵概率。

Terrain 不能按普通网格模型的变换推算范围。当前客户端使用 Unity 2022.3；其 [TerrainData.size 文档](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/TerrainData-size.html)定义的是世界单位尺寸，[同版本 Terrain 范围计算](https://github.com/Unity-Technologies/UnityCsReference/blob/2022.3/Modules/Terrain/Public/PaintContext.cs#L182-L202)直接使用地形位置加该尺寸，没有再次乘 Transform 缩放或旋转。这一规则用于已核对的原生 Terrain，不推广到普通 Mesh 或未知自定义地形。苏拉河原点为零、地形边长为 800，不能因对象保存了约 1.1223 的缩放而扩大为约 897.8。

扫描以服务端的 40×40 世界单位区域为单位，完全在交集外的格子不参与粗筛，跨边界格子只保留交集，继续使用原世界网格编号和分布权重。例如亚马河最后一格的显示范围为 `[296,300)`，不会延伸到 304。范围表示鱼饵应落入的区域，不是人物站位或选定的抛竿点。

非零原点地图也必须对齐**世界网格**，而不是从显示坐标零点或纸地图边缘重新划格。例如原点 `-500` 且交集仍覆盖地形起点时，世界首格 `[-520,-480)` 截断为 `[-500,-480)`，对应显示 `[0,4)`；下一格才是 `[4,12)`。惟有诺克河经纸地图裁剪后为 13×13 格，保留原世界编号。库里湖与埃尔克湖原点保留场景数值精度；聊天最多显示两位小数，发生精简时标“区域约”，内部计算和返回的数值边界不取整。

克马羚诺也湖与铜湖不把对象中保存的旋转再次套到地形范围或世界鱼群网格；与纸地图相交后分别覆盖 121、64 格。铜湖纸地图的标定偏移约为 `(-906.3,-884.7)`、比例约 `7.58`、尺寸 `2048×2048`；首格仍是世界 `(-1,-1)`，显示约 `23.913:23.343～25.6:25.6`，末格仍是世界 `(6,6)`，显示约 `73.6:73.6～77.950:77.380`。地形原点仍为 `(-128,-128)`。

[事实] 拉多加湖群岛的场景设置引用外层主地形，其 X/Z 原点均为 `-500`、边长为 `3000`；客户端先采用场景设置中的地形，只有引用无效时才回退活动地形。内层地形的范围 `[500,1500)` 完全位于外层中，不能重复扫描或用它的原点转换整张地图。群岛的换算为 `(世界坐标 + 500) / 5`，覆盖 76×76＝5776 个世界网格；首格显示 `[0,4)`，末格显示 `[596,600)`。依据为当前客户端的离线场景引用和原点初始化调用链，尚未完成群岛新查询的实机验收。

这些边界是**地形与纸地图显示范围的交集，不是水域掩膜**。可选的[离线五点水陆表](fish-query-water.md)会在此范围内、区域粗筛前剔除五点均非水的格子；没有本图数据时未排除陆地，计算结果记录该状态，游戏帮助统一说明。任一点有水即保留，因此混合格仍可能包含陆地，不保证可达。区域估算仍不逐点计算局部水深、底质、水流、结构及距离，实际发鱼保留原有落点环境计算。

## 支持边界

查鱼助手对支持表以外的未知内陆地图直接回复“不支持该地图的区域查询”，不使用零原点猜测、不回退攻略点或场景默认点。拉多加湖群岛已进入支持表，不再按未知地图拒绝。

[事实] 服务端目前优先使用 `14/2` 落点，缺失时才回退 `3/9` 人物位置。区域推荐以正常抛竿包含落点为准；查询不改变该生产路径，也不修改缺失落点时的回退坐标。未知地图的拒绝条件由 `TestFishQueryUnverifiedScenesRemainUnsupported` 覆盖。

挪威海继续使用既有海图候选落点，不套用内陆范围。地图支持与范围仅代表源码已实现，不代表所有地图都已实机验收。

鱼群分布关闭时，各区域没有分布上的优劣，查询只推荐饵料和钓法并说明“不推荐区域”，不虚构获胜坐标。
